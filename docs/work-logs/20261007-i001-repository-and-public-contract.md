# #1 작업 로그 : 저장소 구조, 개발 규칙, 공개 계약 / #1 work log : repository structure, development rules and the public contract

## 2026-10-07

- **출발점**: 사용자가 rePIU와 re2DJ의 웹과 ARM 실행을 위한 공용 x86 CPU 코어 제안을 승인하고 `reexec/rex86` 저장소를 만들었다. 규칙은 rePIU의 AGENTS.md에서 필요한 것만 추려 적용하고, 작업 처리와 GitHub 이슈 연동, 브랜치 머지 규칙도 같이 적용하기로 했다.
- **이슈와 접근**: 작업 시작 시점에는 이 세션의 GitHub 자격 증명이 `reexec` 조직의 저장소를 보지 못해 문서를 #1로 가정하고 작성했다. 사용자가 Claude GitHub App에 저장소 권한을 추가한 뒤 저장소를 세션에 붙였고, 비어 있는 저장소임을 확인한 뒤 이슈 [#1](https://github.com/reexec/rex86/issues/1)을 만들었다. 가정한 번호와 같다.
- **`main` 초기 커밋**: 원격이 비어 있어 `main`이 없었다. 규칙은 `main`에 직접 커밋하지 않는 것이지만 브랜치의 base가 필요하므로, `LICENSE`, `VERSION`, `.gitignore`, `CLAUDE.md`만 담은 bootstrap 커밋 하나를 `main`에 두고 나머지는 전부 `work/i001-repository-and-public-contract` 브랜치에 커밋했다. 이 예외는 저장소 생성 때 한 번뿐이다.
- **규칙 선별**: rePIU AGENTS.md의 핵심 원칙, 응답 태도, 요구사항 처리 절차, 문서 작성 규칙, 분석과 지식 기반 규칙, 구현 규칙의 공용 항목, 작업 단위 규칙, Git 작업 규칙, 개발 철학을 가져왔다. 게스트 형식(DOS/4GW), HLE 경계, `EXE_DESIGN` 문서, 플랫폼 디렉터리와 실행 모델(`direct`/`cache`) 규칙, Win32 예외 진입 예외 조항은 코어에 해당하지 않아 뺐다. 그 자리에 코어 경계 규칙(OS 헤더 금지, 콜백으로만 OS 접근, 백엔드에 x86 의미 금지, 더미 금지, 실행 시점 엔진 선택)과 소비자 규칙(FetchContent tag 고정, 계약 변경 시 두 소비자 영향 기록)을 두었다. 작업 처리는 re2DJ #1이 정리한 절차(이슈 생성, `Closes #N`, CI 통과 뒤 squash merge, `pull --ff-only`, 로컬 tag)를 머지 순서 8단계로 명시했고, 브랜치 이름 `work/iNNN-slug`를 정했다.
- **구현**
  - `include/rex86/cpu_state.h`: `CpuState`(GPR 8개, EIP, EFLAGS, 세그먼트 6개와 디스크립터 캐시, 80비트 x87 상태), SDM 초기값의 `Reset`.
  - `include/rex86/guest_memory.h`, `src/guest_memory.cpp`: `GuestMemory`(base가 null이면 identity)와 `PageAttributeTable`. 범위와 페이지 속성을 통째로 검사한 뒤 접근, 바이트 단위 little-endian 조립.
  - `include/rex86/environment.h`: `StopReason`, `FaultKind`, `Event`, `Descriptor`, `Features`, `Environment`, `CodeCacheServices`.
  - `include/rex86/cpu.h`, `src/cpu.cpp`: 게이트 집합, 256비트 pending 인터럽트(높은 벡터 먼저), `Run`은 `kNoEngine`, `RequestStop`, `InvalidateCode`.
  - `tests/unit/`: 네 테스트 113 checks. `src/tools/probe/`: `rex86_probe`.
  - `CMakeLists.txt`, `CMakePresets.json`, `scripts/build_web_wasm.sh`, `.github/workflows/ci.yml`(다섯 호스트).
- **검증**
  - Linux x64 GCC 13 Debug(`linux-x64-debug` preset, `-DREX86_WARNINGS_AS_ERRORS=ON`): 빌드, `ctest` 2/2 통과, `rex86_unit_tests` checks 113 failures 0, probe `version=0.0.1 pointer_bytes=8 page_size=4096 cpu_state_bytes=240`, `engine=none run=no_engine retired=0 eflags=0x00000002 x87_cw=0x037f`.
  - Linux x64 Clang 18 Release(`-Werror`): 처음 `-Wunused-private-field`로 실패(`environment_`, `code_cache_`가 아직 쓰이지 않음). 접근자 `environment()`, `code_cache()`를 더해 해결하고 테스트에 검사를 추가했다. 빌드와 2/2 통과.
  - `CMakePresets.json`은 JSON으로, `ci.yml`은 YAML로 읽어 다섯 작업 이름을 확인했고 `build_web_wasm.sh`는 `bash -n` 통과.
  - **확인하지 못한 것**: Windows x86(MSVC), Linux i386(이 머신에 32비트 libc 없음), Linux AArch64, wasm32(emcc 없음). 브랜치를 push하면 CI가 확인한다. 저장소 접근이 열린 뒤 push하고 결과를 이 로그에 덧붙인다.
- **CI 결과** ([run 1](https://github.com/reexec/rex86/actions/runs/37556697707), 커밋 `c930055`): 여섯 작업 모두 통과. `windows-x86`(MSVC, `-A Win32`), `linux-x64 (gcc)`, `linux-x64 (clang)`, `linux-x86`(i386 Debian 컨테이너), `linux-arm64`(`ubuntu-24.04-arm`), `wasm32`(Emscripten 3.1.74, Node). probe 줄은 arm64가 `version=0.0.1 pointer_bytes=8 page_size=4096 cpu_state_bytes=240`, wasm32가 `version=0.0.1 pointer_bytes=4 page_size=4096 cpu_state_bytes=240`이고, 둘째 줄 `engine=none run=no_engine retired=0 eflags=0x00000002 x87_cw=0x037f`는 로컬 x64와 같다. 지시서의 완료 조건대로 `pointer_bytes`만 호스트에 따라 다르다.
- **남은 것**: 없음. 머지는 사용자 요청 시 `AGENTS.md` 절차대로.

*Starting point: the user approved the shared x86 CPU core for rePIU's and re2DJ's web and ARM execution and created `reexec/rex86`, asking that rePIU's rules be applied from the start with only what is needed, including task handling, GitHub issue integration and the branch merge rules. Issue and access: at the start this session's GitHub credential could not see the `reexec` organization's repository, so the documents were written assuming #1; after the user granted the Claude GitHub App access, the repository was attached, found empty, and issue [#1](https://github.com/reexec/rex86/issues/1) was created, matching the assumption. Initial `main` commit: the remote was empty, so although the rule is never to commit to `main` directly, one bootstrap commit holding only `LICENSE`, `VERSION`, `.gitignore` and `CLAUDE.md` was placed on `main` as the branch's base, with everything else committed on `work/i001-repository-and-public-contract`; this exception happens once, at repository creation. Rule selection: rePIU's core principles, tone, requirement procedure, documentation, analysis and knowledge-base rules, the shared implementation rules, task unit rules, Git rules and development philosophy were carried over; the guest-format, HLE-boundary, `EXE_DESIGN`, platform-directory, execution-model and Win32 exception-entry rules were dropped as not applying to a core, and core boundary rules (no OS headers, OS access through callbacks only, no x86 semantics in backends, no dummies, run-time engine choice) and consumer rules (FetchContent tag pinning, recording both consumers' impact on contract changes) took their place; task handling follows re2DJ #1's procedure written out as an eight-step merge order, with branch names `work/iNNN-slug`. Implementation: `CpuState` with SDM reset values; `GuestMemory` (null base is identity) and `PageAttributeTable` with whole-range checks and byte-wise little-endian assembly; `StopReason`, `FaultKind`, `Event`, `Descriptor`, `Features`, `Environment`, `CodeCacheServices`; `Cpu` with a gate set, a 256-bit pending-interrupt set (highest vector first), `Run` returning `kNoEngine`, `RequestStop` and `InvalidateCode`; four unit tests (113 checks) and `rex86_probe`; the build files and a five-host CI. Verification: Linux x64 GCC 13 Debug and Clang 18 Release build with `-Werror` and pass 2/2 tests (Clang first failed on `-Wunused-private-field`, fixed by adding the `environment()` and `code_cache()` accessors); presets and CI parsed, the wasm script passes `bash -n`. Not verified here: Windows x86, Linux i386 (no 32-bit libc on this machine), Linux AArch64 and wasm32 (no emcc); CI checks them once the branch is pushed. CI results ([run 1](https://github.com/reexec/rex86/actions/runs/37556697707), commit `c930055`): all six jobs pass (`windows-x86` on MSVC with `-A Win32`, `linux-x64` gcc and clang, `linux-x86` in the i386 Debian container, `linux-arm64` on `ubuntu-24.04-arm`, `wasm32` on Emscripten 3.1.74 under Node); the probe prints `version=0.0.1 pointer_bytes=8 page_size=4096 cpu_state_bytes=240` on arm64 and `pointer_bytes=4` with the same other values on wasm32, and the second line `engine=none run=no_engine retired=0 eflags=0x00000002 x87_cw=0x037f` matches local x64, so only `pointer_bytes` differs by host as the work order requires. Nothing remains; the merge follows `AGENTS.md` when the user asks.*
