# #27 작업 로그 : 벤치마크 하네스 / #27 work log : the benchmark harness

이슈: [#27](https://github.com/reexec/rex86/issues/27) | 설계: [20261009-i027](../design/20261009-i027-benchmark-harness.md) | 지시서: [20261009-i027](../work-orders/20261009-i027-benchmark-harness.md)

## 2026-10-09

- **출발점**: v0.0.14(1단계 완료) 뒤 README 달성도 표의 "벤치마크 하네스와 비교군 측정" 행. 사용자의 요청은 "벤치마크 하네스 작업"이고, 비교군 측정은 웹 데모 뒤로 두었다(설계 범위).
- **설계**: 공개 계약만 쓰는 도구(`src/tools/bench/`), 실행 중 조립하는 합성 커널 다섯과 혼합 워크로드, C++ 참조 모델로 매 바퀴 검증, 프레임 = `Run(budget)` 한 번, 기판 넷의 클럭과 IPC 가정(1.0, 추정)으로 환산한 실시간 비율, probe와 같은 key=value 출력, `--smoke`의 ctest 등록, `--dump`로 비교군용 이미지 내보내기.
- **구현**: `asm.{h,cpp}`(커널이 쓰는 인코딩만 아는 바이트 어셈블러. ModRM/SIB, EBP 기저의 disp8 0, ESP 기저의 SIB, 레이블과 rel8/rel32 고정), `workloads.{h,cpp}`(커널 `alu`, `memory`, `call`, `string`, `x87`와 드라이버, 4 MiB 배치, 참조 모델), `runner.{h,cpp}`(`Machine`, 프레임 루프, 통계, 기판표), `main.cpp`(인자와 출력). CMake에 `rex86_bench_lib`, `rex86_bench`, ctest `rex86_bench_smoke`, `$<CONFIG>` 정의, Emscripten의 `-sNODERAWFS`. `windows-x86-release` 빌드/테스트 프리셋.
- **구현 중 고친 것**: smoke가 "정확히 두 바퀴"를 가정했는데 한 프레임(100만 명령)에 여러 바퀴가 들어가므로 "두 바퀴 이상"으로 바꿨다. Zydis는 `FADDP ST(1),ST(0)`과 `FXCH`의 서명을 `r80`(명시 피연산자 하나)으로 보고하므로 테스트의 기대값을 맞췄다. 바퀴 누적 카운터를 `Machine` 멤버로 두어 기계 여럿이 섞여도 틀리지 않게 했다.
- **단위 테스트** `tests/unit/bench_test.cpp`: 인코딩 44종을 코어 디코더로 확인(mnemonic, 서명, 길이), 분기 고정과 디코더가 보는 목적지, 닿지 않는 short 분기와 미결 레이블의 실패, 이미지 빌드와 `mixed`의 기대값 합성, 여섯 워크로드의 두 바퀴 검증, 프레임 분할(예산이 바퀴보다 작을 때 프레임마다 정확히 예산만큼 retire, 바퀴가 예산 끝에 정확히 걸리는 경우, 어떤 바퀴도 끝나지 않는 경우의 실패 보고), 틀린 기대값의 검출, 페이지 속성과 초기 상태, 백분위 색인, 기판 프레임 명령 수.
- **검증**:
  - WSL2 GCC 13 Debug(`-Werror`): 단위 테스트 checks 830 failures 0, ctest 5/5(bench smoke 10초 포함).
  - WSL2 GCC ASan/UBSan Debug(`-Werror`, CI `linux-x64-sanitize`와 같은 설정): ctest 5/5, 새니타이저 보고 0.
  - Windows MSVC 19.50 x86 Release와 Debug(`-Werror`): 경고 0, Debug ctest 4/4(bench smoke 18초 포함).
  - `--dump`가 `image.bin`(578바이트)과 `image.txt`를 쓰고, `--engine translator`는 `engine_available=false`로 거절한다.
  - **측정**(Release, 다른 부하 없음, AMD Ryzen 5 5600X): x86-64 GCC에서 alu 3.82, memory 4.36, call 4.45, string 2.57, x87 3.72, mixed 3.57 MIPS. Windows x86 MSVC에서 2.36, 2.35, 2.35, 1.82, 2.04, 2.23 MIPS. 여섯 모두 `verified=ok`. 기판 환산(mixed, IPC 1.0): 400 MHz 기판 실시간 비율 0.0089, 1.4 GHz 기판 0.0026. 기록은 [분석](../analysis/interpreter-performance.md).
  - Clang, i386 Linux, AArch64, wasm32는 이 환경에 도구가 없어 push 뒤 CI로 확인한다.
- **문서**: 설계, 지시서, 가이드 `docs/guides/benchmark.md`, 분석 `interpreter-performance.md`와 색인, ARCHITECTURE 3절과 4절, README 달성도 표(진행 중: 하네스 완료, 비교군 미착수)와 현재 수치 문단.
- **코어는 바꾸지 않았다**. 공개 헤더와 `src/`의 비도구 부분은 그대로다.
- **남은 것**: wasm32와 AArch64의 수치(CI 러너는 smoke만), 비교군 측정(웹 데모 뒤, `--dump` 이미지 사용), 피크 RSS 계측(호스트 전용 파일), 번역 백엔드의 `BenchCodeCache`와 SMC 워크로드.

*Starting point: after v0.0.14 (phase 1 complete), the attainment table's "benchmark harness and comparator measurement" row; the user asked for the harness, and comparator measurement waits for the web demo (design scope). Design: a tool on the public contract alone (`src/tools/bench/`), five synthetic kernels and a mixed workload assembled at run time, verification of every lap against a C++ reference model, a frame as one `Run(budget)`, real-time ratios from the four boards' clocks and an inferred IPC of 1.0, key=value output as the probe's, `--smoke` in ctest and `--dump` for comparator images. Implementation: `asm` (a byte assembler knowing only the kernels' encodings, with ModRM/SIB, EBP-base disp8 0, ESP-base SIB, labels and rel8/rel32 fixups), `workloads` (the kernels, drivers, the 4 MiB layout, the models), `runner` (`Machine`, the frame loop, statistics, the board table), `main`; CMake adds `rex86_bench_lib`, `rex86_bench`, ctest `rex86_bench_smoke`, the `$<CONFIG>` definition and `-sNODERAWFS` under Emscripten, plus the `windows-x86-release` presets. Fixed along the way: the smoke assumed exactly two laps where a million-instruction frame holds several (now at least two); Zydis reports `FADDP ST(1),ST(0)` and `FXCH` with the signature `r80`; the lap counter became a `Machine` member. Unit tests cover 44 encodings through the core's decoder, branch fixups and decoder-seen targets, failing short branches and unbound labels, image building and `mixed`'s expectation, two verified laps of every workload, frame slicing (exact budgets with a lap shorter than the budget, a lap ending exactly at the budget, failure when no lap completes), a wrong expectation caught, page attributes and initial state, percentile indices and the boards' frame worth. Verification: WSL2 GCC 13 Debug with `-Werror` (830 checks, 0 failures, ctest 5/5), GCC ASan/UBSan (ctest 5/5, no reports), MSVC 19.50 x86 Release and Debug (no warnings, Debug ctest 4/4), `--dump` writes the 578-byte image and its metadata, `--engine translator` is refused. Measurement in Release on an idle AMD Ryzen 5 5600X: x86-64 GCC 3.82 / 4.36 / 4.45 / 2.57 / 3.72 / 3.57 MIPS (alu, memory, call, string, x87, mixed) and Windows x86 MSVC 2.36 / 2.35 / 2.35 / 1.82 / 2.04 / 2.23, all `verified=ok`, mixed real-time ratios 0.0089 (400 MHz boards) and 0.0026 (1.4 GHz) at IPC 1.0, recorded in the analysis. Clang, i386 Linux, AArch64 and wasm32 go to CI after the push. Documents: design, work order, the guide, the analysis and its index, ARCHITECTURE sections 3 and 4, README's attainment row and current figures. The core is unchanged. Remaining: wasm32 and AArch64 figures, comparator measurement after the web demo, peak-RSS instrumentation, the backend's `BenchCodeCache` and an SMC workload.*
