# #19 작업 로그 : x87 1차 / #19 work log : x87 increment 1

## 2026-10-08

- **SoftFloat 도입**: berkeley-softfloat-3의 HEAD(`a0c6494`)를 먼저 가져왔으나 3e 이후의 bf16 코드가 8086 specialization에서 빌드되지 않았다. 3e 이후 커밋이 8086 specialization을 바꾸지 않음을 diff로 확인하고 Release 3e(`f74b1e4`)로 다시 vendoring했다(302개 소스). 이 저장소의 `platform.h`는 이식 가능한 C(빌트인·128비트 내장 미사용)와 스레드 로컬 전역을 쓴다. C++에서 `_Thread_local` 선언이 non-TLS로 컴파일되어 링크가 실패했고, C++에서는 `thread_local`을 쓰고 `softfloat.h`보다 `platform.h`를 먼저 포함하도록 고쳤다.
- **구현**: `src/fpu/`(80비트 값과 분류, SoftFloat 위의 예외 의미), `src/interp/exec_x87*.cpp`, `x87_stack`, `x87_access`. `FaultKind::kFloatingPoint` 추가. WAIT의 #MF를 `exec_segments`에서 x87 쪽으로 옮겼다. 기존 단위 테스트의 "미구현 명령" 예를 FLD1에서 FSIN으로 바꿨다.
- **SST 부작용 정리**: x87이 실행되자 SST `67A5.MOO` #442(자기 HLT를 덮어쓰는 REP MOVSW)가 덮어쓴 바이트를 따라 IN까지 가서 "경계"로 분류가 바뀌었다. 386은 HLT를 이미 prefetch했으므로 하네스가 "다음 명령이 덮어써진 trailing HLT"를 가장 먼저 표현 불가로 분류하도록 고쳤다. far CALL이 HLT 자리에 push하고 분기하는 경우(`669A.MOO` #611)는 제외했다. SST 수치는 #17과 같다.
- **호스트 CPU 대조 fuzz**: `tests/host/linux/x87_fuzz.cpp`. 첫 실행은 2만 건 중 2,974건(14.9%) 불일치였다. `--replay` 모드로 한 건씩 재현하며 고쳤다. 불일치 수의 추이는 2,974/2만 → 1,827/5만 → 626 → 555 → 398 → 187 → 161 → 140 → 42 → 29 → 0이다. 고친 것:
  - CW 적재 정규화(`(v & 0x1F3F) | 0x40`), FFREE/FFREEP의 C1, FFREEP의 pop(ST(0) 태그), FCOMI·FCMOV의 C1 유지, FLD ST(i)·FXTRACT의 언더플로 우선, FCMOV 언더플로 응답, FSTPNCE의 no-check-empty
  - 저장 명령의 #D 제거, FSQRT 음수의 #IA 우선, pseudo-denormal 정규화(SoftFloat 3e의 덧셈이 올림을 잃음)
  - SDM 4.9.2 우선순위: 0으로 나눔 > #D, 스택 폴트 > 메모리 피연산자 변환 예외, QNaN·무효 형식 > 메모리 #D. 메모리 피연산자를 조용히 변환하고(SNaN 유지) denormal 여부를 `OperandHints`로 넘기는 구조로 바꿨다. FLD m32/m64는 #D가 마스크되지 않아도 적재한다
  - 비교의 마스크 안 된 #D(관계는 보고, pop만 보류)
  - FPREM/FPREM1: 부분 감소 N을 호스트에서 직접 측정했다(800건, N = 32 + D mod 32, 전부 일치). 부분 감소의 C 비트, FPREM1의 부분 감소 절사, NaN·무효·억제 시 C1/C2만 클리어, x rem ∞의 정규화와 언더플로 응답
  - 마스크 안 된 #O/#U의 이중 범위 초과 포화(±∞ / ±0, FSCALE에서 측정)
- **SDM과 다른 호스트 동작 1종**: 마스크 안 된 #IA의 비교에서 AMD Zen 3는 unordered를 쓴다. SDM 표는 "flags not set"이다. 코어는 SDM을 따르고 fuzz는 `vendor_deviations`로 따로 센다. 단위 테스트로 규칙을 고정했다.
- **fuzz 자체 버그**: 디버그 빌드에서 컴파일러가 inline asm 입력을 RBX에 배정해 segfault가 났다. 입력 레지스터를 명시적으로 고정했다(x86-64: RCX/R9, i386: 스택 경유).
- **검증**
  - **호스트 CPU 대조(최종 바이너리)**: 시드 200~219 × 200만 = **4,000만 건, 불일치 0**, `vendor_deviations` 251,332(0.63%). 그 이전 바이너리로도 4,400만 건 불일치 0이었다(시드 100~119 × 200만, 9~16 × 50만).
  - 단위 테스트 checks 414 failures 0(x87 블록 9개: 데이터 경로, #MF 전달과 위치, 비대기형 명령, FNSTENV 레이아웃과 FIP/FOP/FDP, FNSAVE/FRSTOR 왕복, 저장 폴트 시 x87 무변경, FCOMI 플래그, 마스크 안 된 #IA 비교, Features).
  - SST 실행 비교: executed 1,741,900, mismatches 0(#17과 같음).
  - 로컬 빌드: GCC release·debug, Clang debug(`-Werror`)와 ctest 통과. SoftFloat 302개 파일을 clang으로 wasm32/aarch64/i686 대상 문법 검사해 통과했다. MSVC(Windows x86), 실제 i386·wasm32·AArch64 실행은 push 뒤 CI에서 확인한다(아직 push하지 않음).
- **소비자 영향**: `FaultKind::kFloatingPoint` 추가(#17의 `kStackFault`에 이어). 머지 뒤 rePIU·re2DJ 어댑터의 매핑과 tag 갱신 작업이 필요하다.
- **남은 것**: x87 2차(초월함수), Intel 호스트에서의 대조, 정수 명령 호스트 대조 fuzz와 trace.

*SoftFloat: the upstream HEAD (`a0c6494`) failed to build (post-3e bf16 code against the 8086 specialization); a diff showed no later commit touches that specialization, so Release 3e (`f74b1e4`, 302 sources) was vendored, with this repository's portable `platform.h`; C++ saw `_Thread_local` as non-TLS and failed to link until C++ used `thread_local` and included `platform.h` before `softfloat.h`. Implementation: `src/fpu/`, `src/interp/exec_x87*.cpp`, `x87_stack`, `x87_access`, `FaultKind::kFloatingPoint`, WAIT's #MF moved to the x87 side, and the unit test's unimplemented example changed from FLD1 to FSIN. SST: with x87 running, `67A5.MOO` #442 (a REP MOVSW overwriting its own HLT) followed the new bytes to an IN and became a "boundary"; the harness now classifies "the next instruction is an overwritten trailing HLT" as unrepresentable first (the 386 had prefetched it), excluding far CALLs that push over the spot and branch away (`669A.MOO` #611); SST figures equal #17's. Host fuzz: the first run mismatched 2,974 of 20,000 (14.9%); replaying cases one by one brought it through 1,827/50k, 626, 555, 398, 187, 161, 140, 42 and 29 to 0 — CW canonicalization, C1 handling of FFREE(P)/FCOMI/FCMOV, FFREEP's pop, underflow before overflow for FLD ST(i) and FXTRACT, FCMOV's underflow response, FSTPNCE; no #D on stores, #IA before #D for negative FSQRT, pseudo-denormal canonicalization; SDM 4.9.2 priority with silent memory conversion and `OperandHints`, FLD loading denormals under unmasked #D; compares under unmasked #D; FPREM's N measured directly (800 cases, N = 32 + D mod 32), its condition codes, FPREM1's partial truncation and x rem ∞; and saturation beyond the adjusted range. One host behavior deviates from the SDM — AMD writes unordered on unmasked-#IA compares where the SDM says flags are not set — so the core follows the SDM, the fuzz counts `vendor_deviations`, and a unit test pins the rule. A debug build segfaulted when the compiler put an inline-asm input in RBX; the registers are now pinned. Verification: the final binary over seeds 200–219 × 2M — **40M cases, zero mismatches**, 251,332 vendor deviations (0.63%), after 44M clean cases on earlier binaries; unit tests at checks 414 failures 0 with nine x87 blocks; SST unchanged at 1,741,900 executed and zero mismatches; GCC release/debug and Clang debug (`-Werror`) with ctest locally, SoftFloat syntax-checked for wasm32/aarch64/i686 with clang, MSVC and real i386/wasm32/AArch64 runs left to CI after the push (not pushed yet). Consumer impact: `FaultKind::kFloatingPoint` joins #17's `kStackFault`, needing adapter mappings and tag updates after the merge. Remaining: x87 increment 2 (transcendentals), a run on an Intel host, and the integer host-comparison fuzz and traces.*
