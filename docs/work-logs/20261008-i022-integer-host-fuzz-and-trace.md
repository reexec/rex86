## 2026-10-08

- **출발점**: #21이 정한 최소 사양(P6 정수 + P6 x87 + MMX + SSE)과 v0.0.11 직후 분석의 1번 항목(정수 명령 호스트 대조, trace, 호스트 간 재생, ASan/UBSan CI). #21 브랜치 위에 이어서 작업했다.
- **trace**(지시서 1단계): `src/trace/`에 형식과 `trace::Replay`, `src/tools/trace/`에 `rex86_trace`(`--dump N`, `--quiet`). 영역은 xorshift32 채움에 patch만 얹어, 정수 한 건이 약 170바이트다. 형식 왕복, 결정적 채움, 재생 일치와 불일치 검출을 단위 테스트(`trace_test.cpp`)로 확인했다.
- **정수 fuzz**(2단계): `tests/host/linux/int_fuzz.cpp`. 설계 전에 scratchpad에서 시험한 TF 단일 스텝 그대로다. 형태 1,112개(149개 mnemonic). 레지스터 적재 스텁은 처음에 코드 페이지 앞부분(41바이트)에 있었는데, trace마다 그 바이트가 patch로 들어가 묶음이 커져서 보호 영역 뒤의 별도 페이지(0x15000)로 옮기고 `jmp`로 POPFD에 닿게 했다(한 건 212바이트에서 172바이트). 지시서의 `--replay`는 만들지 않았다. 대신 `--failures`가 불일치를 trace로 쓰고 `rex86_trace --dump`가 펼친다(어느 호스트에서든 재현되므로 목표 9에 더 맞다). `--stats`(mnemonic별 retire/폴트)와 `--only`를 더했다.
- **fuzz 자체의 버그 둘**: (1) BT 계열의 비트 오프셋 레지스터를 작은 값으로 바꾸는 코드가 그 레지스터가 ESP일 때 스택을 영역 밖으로 보내 fuzz 프로세스가 SIGSEGV로 죽었다. 처리기에 "게스트 밖의 신호" 진단 출력을 넣어 찾았고, ESP는 건드리지 않게 고쳤다. (2) Zydis에 SAL mnemonic이 없어(D0 /6은 SHL로 디코드) 컴파일 오류.
- **P6 정수**(3단계): `exec_post386.cpp`(CMOVcc, BSWAP, XADD, CMPXCHG, CMPXCHG8B, UD0/1/2), `Features::cmov`(CMOVcc, FCOMI 계열, FCMOVcc), POPF/IRET 쓰기 마스크에 AC와 ID. 단위 테스트 `post386_test.cpp`.
- **불일치 0까지**(4단계). 첫 2만 건에서 21건이었다. 고친 것(자세히는 [분석](../analysis/integer-host-comparison.md) 2절):
  - XADD [ecx+d], ch: 원본 레지스터를 먼저 써서 주소가 바뀌었다(코어 버그). 메모리 목적지는 저장을 먼저 한다.
  - 폴트 주소: 페이지를 넘는 접근은 처음 닿지 못하는 바이트(CR2)를 보고하게 했다(`FirstInaccessible`).
  - ENTER: 최종 ESP 쓰기 시험(`ProbeWrite`, SDM의 #PF 조건)과, display 복사의 (E)BP를 스택 크기로 줄이는 것(SDM 의사 코드).
  - 읽기 전용 세그먼트: 설계에서 예상한 CS override 쓰기 #GP. 평탄 경로가 `writable`을 보지 않았다. 읽고 쓰는 목적지는 읽기 전에 검사해야 했다(`RequireWritable`: `ReadOperand`의 쓰기 피연산자, BT 계열의 레지스터 오프셋 경로, CMPXCHG8B).
  - CMPS: ES:(E)DI를 먼저 읽는다. PAUSE: NOP.
  - BOUND: 첨자가 하한보다 작으면 상한을 읽기 전에 #BR(호스트). 처음에는 하한 비교만 앞으로 옮겼는데 SST에서 6건이 깨졌다(386EX는 상한이 세그먼트 limit을 넘으면 #GP). 두 경계의 limit 검사를 먼저 하고(`CheckSegment`) 하한, 상한 순으로 고쳐 둘 다 만족시켰다.
- **세대 차이 하나**: 반복 도중 폴트 난 REP CMPS/SCAS에서 호스트(Intel)는 EFLAGS가 명령 시작 때 값이었다. 코어를 그렇게 바꾸자 sanitizer 빌드로 돌린 SST에서 72건이 깨졌다(386EX는 마지막 반복의 플래그). SDM이 정하지 않는 곳이라 코어는 SST 쪽을 유지하고 fuzz에서 마스크했다. 분석 3절.
- **SST 회귀 실행에서의 혼동**: 처음 `rex86_sst --execute`가 93,431건 불일치를 냈는데, 압축을 푼 MOO 디렉터리 옆에 `80386.csv`가 없어 미정의 플래그 마스크(f_umask)가 빠진 탓이었다(러너는 상위 디렉터리에서 찾는다). 디렉터리를 옮기자 원래 수치로 돌아왔다. 코드 문제는 아니다.
- **x87 fuzz를 Intel에서**(#19의 "Intel 미확정"): 이 작업 환경의 호스트는 Intel Xeon Cascade Lake(family 6 model 85 stepping 7)다. 2,000만 건 중 9건(FPREM, FPREM1, FSCALE)이 어긋났다. x rem ∞와 0배 FSCALE에서 ST(0)가 denormal이고 #U가 마스크되지 않았을 때 Intel은 ST(0)를 #U 없이 그대로 돌려주고, #19가 따른 AMD는 #U와 지수 조정 값을 낸다. SDM의 FPREM, FSCALE 결과 표가 "ST(0)"라고 적으므로 코어를 SDM과 Intel로 바꾸고(`PassThrough`), x87 fuzz에 AMD 응답을 `vendor_deviations`로 세는 판정을 더했다. 마스크 안 된 #IA 비교의 이탈은 Intel에서도 같았다.
- **x87 `--record`**: 일치한 사례를 trace로 쓰고 그 자리에서 재생해 기록을 검사한다. 처음에는 한 건이 780바이트라(출력 이미지 0 patch, 데이터 128바이트 전부) 메모리 피연산자 크기만 patch하고 바뀐 데이터 바이트만 diff로 남겨 약 400바이트로 줄였다.
- **trace 묶음**(5단계): `tests/traces/int32.rxt`(`rex86_int_fuzz 12000 2201`, 12,000건, 2.07 MB), `tests/traces/x87.rxt`(`rex86_x87_fuzz 2600 2202`, 제조사 이탈 13건을 뺀 2,587건, 1.04 MB). `.gitattributes`에 `*.rxt binary`. ctest `rex86_trace_corpus`가 모든 호스트에서 재생한다.
- **CMake와 CI**: `rex86_trace_format`, `rex86_trace`(Emscripten `-sNODERAWFS=1`), `rex86_int_fuzz`(Linux x86, `CMAKE_SIZEOF_VOID_P` 4, ctest `50000 1`), `REX86_SANITIZE`. `linux-x86-debug` 프리셋에 `CMAKE_C_FLAGS=-m32`를 더했다(multilib 개발 환경에서 Zydis와 SoftFloat가 64비트로 컴파일돼 링크가 깨졌다. i386 컨테이너에는 영향 없음). CI에 `linux-x64-sanitize`. 설계는 Clang이라 적었지만 이 환경의 Clang 18에 sanitizer 런타임(compiler-rt)이 없어 검증할 수 없었으므로, 로컬에서 확인한 GCC로 바꿨다.
- **i386 단위 테스트 하나**: `x87_test.cpp`의 `== 3.141592653589793` 비교가 i386 GCC의 x87 확장 정밀도(FLT_EVAL_METHOD 2) 때문에 실패해, 비트 패턴 비교로 바꿨다.
- **문서**: 분석 `integer-host-comparison.md`(새로), `x87-host-comparison.md`(Intel 결과, 이탈 2종), kb `trap-flag-single-step.md`, 가이드 `integer-host-fuzz-and-traces.md`와 x87 가이드, ARCHITECTURE, README(경고 문단, 달성도 표, 현재 수치), 색인. 고친 문서의 em dash와 가운데 점을 지웠다.

*Starting point: #21's minimum specification and item 1 of the post-v0.0.11 analysis, stacked on the #21 branch. Traces: the format and `trace::Replay` in `src/trace/`, `rex86_trace` (`--dump N`, `--quiet`), a fill-plus-patches layout of about 170 bytes per integer case, and unit tests for the round trip, deterministic fill and replay. The integer fuzz is the trap-flag single step tried before the design, over 1,112 forms (149 mnemonics); its register-loading stub moved from the code page to its own page past the guard (0x15000, reached by a `jmp` to the POPFD), since every trace carried it as a patch (212 to 172 bytes a case). Instead of the work order's `--replay`, `--failures` writes mismatches as traces that `rex86_trace --dump` spells out, reproducible on any host (closer to goal 9); `--stats` and `--only` were added. Two bugs of the fuzz itself: shrinking a BT bit-offset register that happened to be ESP pushed the stack out of the region and killed the process (found through a new "signal outside the guest" diagnostic), and Zydis has no SAL mnemonic. P6 integer: `exec_post386.cpp`, `Features::cmov`, AC/ID in POPF/IRET, unit tests. To zero mismatches (21 in the first 20,000 cases): XADD [ecx+d], ch changed its own address (a core bug); page-straddling faults now report the first unreachable byte; ENTER probes the final ESP and walks the display at the stack width; read-only segments are checked on writes, before the read of a read-modify-write destination; CMPS reads ES:(E)DI first; PAUSE is a NOP; BOUND first moved the lower-bound compare ahead, which broke 6 SST cases, and now checks both bounds' limits first, then lower, then upper. One generation difference: the Intel host reports a mid-way REP CMPS/SCAS fault with the starting flags, the 386EX with the last iteration's (72 SST cases broke when the core tried the former), so the core keeps the SST behavior and the fuzz masks it. A first SST rerun showing 93,431 mismatches came from the gunzipped MOO directory lacking `80386.csv` beside it, not from code. The x87 fuzz on this Intel Cascade Lake: 9 cases in 20M (FPREM, FPREM1, FSCALE) where a denormal ST(0) passed through with #U unmasked comes back unchanged without #U on Intel but with #U and the adjusted value on AMD, which #19 had followed; the SDM tables say "ST(0)", so the core now follows the SDM and Intel and the fuzz counts AMD's response apart; the unmasked-#IA compare deviation shows on Intel too. x87 `--record` checks each recorded case by replaying it, and shrank from 780 to about 400 bytes a case. Corpus: `int32.rxt` (12,000 cases, 2.07 MB) and `x87.rxt` (2,587, 1.04 MB), `*.rxt binary` in `.gitattributes`, replayed by ctest everywhere. CMake and CI: the new targets, `REX86_SANITIZE`, `-m32` for C in the `linux-x86-debug` preset (multilib builds compiled Zydis and SoftFloat 64-bit), and a `linux-x64-sanitize` job with GCC rather than the design's Clang, whose sanitizer runtime is missing here so it could not be verified. An i386 unit test compared a double against a literal under x87 excess precision and now compares bit patterns. Documents as listed, em dashes and middle dots removed from the touched files.*
