# #29 작업 로그 : 1b — MMX와 SSE / #29 work log : phase 1b — MMX and SSE

## 2026-10-09

- **출발점**: v0.0.15 머지 뒤 README 달성도 표의 1b. 측정 호스트는 이 작업 환경의 AMD Ryzen 5 5600X(Zen 3, family 19h)이고, WSL2 Ubuntu 24.04(GCC 13, multilib)에서 x86-64와 i386 프로세스로 돌렸다.
- **측정 먼저**: Zydis는 SSE가 더한 MMX 정수 명령(PSHUFW 등)을 `PENTIUMMMX`로, FXSAVE를 `FXSAVE`로 분류한다. 그래서 기능 판정은 ISA 집합만으로 할 수 없고, Mendocino(FXSR 있음, SSE 없음)와 K6-2(둘 다 없음)를 가를 `Features::fxsr`가 필요하다. FXSAVE 프로브는 MXCSR_MASK 0x0002FFFF, 예외가 없을 때의 FIP/FDP 0, 슬롯의 남는 바이트 0, MMX 뒤 TOP 0과 태그 유효와 79:64 = FFFF를 보였다(설계 "측정 먼저").
- **증분 1**(커밋 74281b0): 공개 계약(`SseState`, `kSimdFloatingPoint`, `Features::fxsr`, `mmx`/`sse`/`fxsr` 기본 켬), `FeatureEnabled`, `simd_access`(64/128비트 피연산자, 정렬 #GP, 모든 조각을 먼저 검사하는 저장, MMX 진입), `exec_mmx`, `exec_sse`, `exec_fxsave`, 단위 테스트, `rex86_simd_fuzz`(FXRSTOR/FXSAVE 스텁, 신호로 받는 호스트 폴트, 입력 이미지까지 비교).
  - fuzz 자체의 오류 둘: ModRM 없는 형태에 즉값 바이트를 붙이다 그 바이트가 ModRM으로 읽혔고, 상태 워드 생성에서 조건 비트가 TOP과 겹쳤다. Release(-O3)의 GCC가 `std::map<std::vector>`에 잘못된 stringop-overread 경고를 내 64비트 키로 바꿨다.
  - 코어 오류 하나: **EMMS는 TOP도 0으로 만든다**(SDM 표 9-2). 첫 2만 건에서 드러났다.
  - 결과: x86-64 Release 1,000만 건(시드 100~109), i386 Debug 100만 건(시드 200~201), 불일치 0.
- **증분 2 측정**: 프로브 두 개(`ssefp`, 신호 문맥에서 MXCSR을 읽는 `ssexm`)로 SDM이 분명하지 않은 곳을 쟀다. **언더플로는 반올림 전에 판정**하고(x87과 다름), NaN이 있으면 #D가 없고, 마스크 안 된 예외의 플래그는 전계산/후계산 규칙대로이며, FZ는 정확한 결과에도 #U와 #P를 세운다. RCPPS/RSQRTPS는 비정규수를 0으로 보고, 음수의 RSQRT는 플래그 없는 기본 NaN이며, 1.0의 RCP는 0x3F7FF000이다. 처음 신호 처리기에서 MXCSR을 읽었을 때 커널이 초기화한 값이 보여, 신호 문맥(`fpregs->mxcsr`)에서 읽도록 고쳤다.
- **증분 2 구현**: `src/fpu/sse_math`(SoftFloat binary32 위의 SSE 규칙), `exec_sse_float`(요소별 결과 뒤 전계산/후계산 순서의 MXCSR과 #XM), fuzz의 부동소수점 형태와 RCP/RSQRT 허용치(상대 2⁻¹¹, RCP의 SDM 구현 정의 구간).
  - 첫 2만 건에서 16건: **한 요소 안에서 #I와 #Z가 #D를 가린다**(음의 비정규수 제곱근, 비정규수/0). SDM 11.5.2의 우선순위대로 고쳤다.
  - CVTPI2PS의 메모리 원본이 MMX 전환을 하지 않는다는 처리는 그룹별 집중 실행(20만 건)으로 확인했다.
  - 결과: x86-64 Release 1,000만 건(시드 300~309, 형태 7,961), i386 Debug 100만 건(시드 400~401), 불일치 0. 허용 241,238건(x86-64)과 21,857건(i386). 그룹별 집중 실행 200만 건 불일치 0.
- **단위 테스트**: `mmx_test.cpp`(포화, 부호, 범위를 넘는 시프트, PMADDWD의 wrap, 이동, PSHUFW/PEXTRW/PINSRW/PMOVMSKB, MASKMOVQ, x87 공유, EMMS, #MF, 폴트 뒤 상태, 기판별 #UD), `sse_test.cpp`(이동, 정렬 #GP, 셔플/언팩/논리, PREFETCH, MXCSR의 예약 비트, FXSAVE 형식, FXRSTOR 왕복과 태그, SSE 없는 FXSAVE), `sse_float_test.cpp`(측정한 규칙 전부). checks 1,026, failures 0. `interp_test.cpp`의 "미구현 명령" 예는 EMMS에서 FEMMS(3DNow!)로 바꿨다.
- **trace**: `tests/traces/simd.rxt`(시드 2901, 2,000건 중 1,959건, 2.04 MB). 허용 사례는 기록하지 않는다. trace 형식에 `kFeatureFxsr`와 `CaseKind::kSimd`를 더했다.
- **SST 러너**: 기본값이 바뀌어 386 시험에 MMX/SSE/FXSAVE가 켜지지 않도록, 러너가 그 셋을 명시적으로 끈다(검증되었던 구성 그대로). SingleStepTests 스위트는 이 환경에 없어 다시 돌리지 못했다. 386 스위트에는 이 명령들이 없으므로 결과는 v0.0.15와 같을 것으로 **추정**한다.
- **빌드와 ctest**(모두 `-Werror`):
  - WSL2 GCC x86-64 Debug와 Release: ctest 6/6(x87 fuzz, SIMD fuzz, 단위 테스트, probe, bench smoke, trace 묶음 넷).
  - WSL2 GCC i386 Debug: ctest 7/7(정수 fuzz 포함).
  - GCC ASan/UBSan(CI `linux-x64-sanitize`와 같은 설정): 처음에 SIMD fuzz가 LeakSanitizer에 걸렸다. 대체 신호 스택을 `malloc`하고 풀지 않았기 때문이며, 정적 버퍼로 바꿨다. 그 뒤 ctest 6/6, 새니타이저 아래 SIMD fuzz 10만 건 불일치 0, 보고 0.
  - Windows MSVC 19.50 x86 Debug: 경고 0, ctest 4/4(새 SIMD 묶음 재생 포함).
  - Clang, AArch64, wasm32는 이 환경에 도구가 없어 push 뒤 CI로 확인한다.
- **남은 것**: Intel과 P6 세대 실물의 대조(특히 EMMS의 TOP, CVTPI2PS, RCP 구간), SSE 없는 FXSAVE의 실물 확인, 소비자 어댑터의 `SseState`와 `kSimdFloatingPoint` 대응(머지 뒤 tag 올림 작업).

*Starting point: phase 1b after the v0.0.15 merge, measured on this workspace's AMD Ryzen 5 5600X (Zen 3) in x86-64 and i386 processes under WSL2 Ubuntu 24.04 (GCC 13, multilib). Measured first: Zydis files the SSE-added MMX integer instructions under `PENTIUMMMX` and FXSAVE under `FXSAVE`, so gating needs names and `Features::fxsr`; the FXSAVE probe showed MXCSR_MASK 0x0002FFFF, zero FIP/FDP without exceptions, zero slot padding, and TOP 0, valid tags and FFFF in bits 79:64 after MMX. Increment 1 (commit 74281b0): the contract, `FeatureEnabled`, `simd_access`, `exec_mmx`, `exec_sse`, `exec_fxsave`, unit tests and `rex86_simd_fuzz`; two fuzz bugs (an imm8 appended to a bare opcode read as a ModRM; condition bits overlapping TOP in the generated status word) and a GCC -O3 false stringop-overread warning were fixed, and one core bug: EMMS zeroes TOP too (SDM table 9-2); 10M x86-64 and 1M i386 cases, zero mismatches. Increment 2 measurements: tininess before rounding (unlike the x87), no #D beside a NaN, the pre/post-computation flag rules for unmasked exceptions, FZ raising #U and #P even for exact results, RCP/RSQRT special values, the RCP of 1.0 being 0x3F7FF000; the first probe read MXCSR after the kernel had reset it and was fixed to read the signal context. Increment 2: `src/fpu/sse_math`, `exec_sse_float` and the fuzz's float forms with an RCP/RSQRT tolerance; 16 mismatches in the first 20,000 cases came from #I and #Z hiding #D within a lane (SDM 11.5.2), fixed; CVTPI2PS's memory source making no MMX transition was confirmed by a focused 200,000-case run; 10M x86-64 and 1M i386 cases over 7,961 forms, zero mismatches, 241,238 and 21,857 tolerated, plus 2M focused cases. Unit tests: 1,026 checks, zero failures; `interp_test.cpp`'s unimplemented example moved from EMMS to FEMMS. Corpus `simd.rxt`: 1,959 cases of 2,000 (seed 2901, 2.04 MB), tolerated cases left out; the trace format gained `kFeatureFxsr` and `CaseKind::kSimd`. Builds and ctest, all with `-Werror`: x86-64 Debug and Release 6/6, i386 Debug 7/7, GCC ASan/UBSan 6/6 after a static signal stack replaced a never-freed `malloc` LeakSanitizer flagged in the SIMD fuzz (plus 100,000 sanitized fuzz cases, zero mismatches and reports), MSVC 19.50 x86 Debug with no warnings and 4/4; Clang, AArch64 and wasm32 go to CI after the push. The SST runner turns MMX, SSE and FXSAVE off explicitly, keeping its verified configuration; the suite is not in this environment, so it was not rerun, and the result is inferred unchanged since the 386 suite has none of these instructions. Remaining: Intel and P6 hardware, FXSAVE without SSE on real hardware, and the consumers' adapters for `SseState` and `kSimdFloatingPoint` (the tag-bump tasks after the merge).*
