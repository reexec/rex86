# #5 작업 로그 : 디코더(Zydis) 도입과 독립 명령 census 도구 / #5 work log : the Zydis decoder and the standalone instruction census tool

## 2026-10-07

- **출발점**: #3 머지 뒤 사용자가 다음 작업 진행을 요청했다. #1 설계의 1단계 첫 작업(census 도구 이식)과 그 전제인 디코더를 함께 진행했다.
- **Zydis**: rePIU `third_party/zydis/`의 v4.1.1 amalgamation 네 파일을 복사하고 SHA-256이 rePIU `THIRD_PARTY_NOTICES.md`의 값과 일치함을 확인했다(`Zydis.c` `1851E6D2…`, `Zydis.h` `CE154FC8…`). `THIRD_PARTY_NOTICES.md`에 기록하고, `rex86_zydis` STATIC 타깃(`ZYDIS_STATIC_BUILD`, 경고 타깃 미적용)으로 빌드했다. 프로젝트 언어에 C를 더했다.
- **디코더**: `src/decode/decoder.{h,cpp}`. `Decoder`는 32비트 legacy 모드 고정, `DecodedInstruction`은 길이, mnemonic 이름, ISA set 이름, rePIU census 형식의 피연산자 서명, x87 판별, 80비트 메모리 피연산자 판별, 제어 흐름 분류(직접/간접 jmp와 call 구분, jcc, ret, int, hlt)와 직접 분기 목적지(`ZydisCalcAbsoluteAddress`)를 제공한다. 공개 계약은 무변경이고 Zydis 타입은 `src/` 내부 헤더에만 나타난다. 소비자 어댑터에 미치는 영향 없음.
- **census**: `src/tools/census/census.{h,cpp}`(로직)와 `main.cpp`(`rex86_census`, Emscripten 제외). 재귀 하강은 직접 jmp/call/jcc 목적지와 fallthrough를 따라가고, 간접 call과 int는 복귀를 전제로 fallthrough로 계속, ret/간접 jmp/hlt/디코드 실패에서 멈춘다. 선형 스윕은 실패 시 1바이트 전진. 보고는 하한/상한, mnemonic별 수와 서명, 서명 누적 커버리지, x87 집계(80비트 메모리, 제어 워드, 환경 save/restore), ISA set 집계. rePIU census의 장기 모드 측정은 설계대로 가져오지 않았다.
- **검증**
  - 단위 테스트 2개 파일 추가(디코더 15개 명령 형태와 실패 경로, census 도달/상한/범위/빈 입력). 전체 `rex86_unit_tests` checks 183 failures 0.
  - 로컬 Windows x86(MSVC `-A Win32`, VS 18, `-DREX86_WARNINGS_AS_ERRORS=ON`) Debug: 경고 없이 빌드, `ctest` 2/2 통과.
  - `rex86_census`를 17바이트 합성 바이너리에 실행: `reached_instructions=7 sweep_decoded=7 sweep_failed=1 x87_total=1 x87_float80_memory=1`, 서명 누적 % 표 출력 확인.
  - **확인하지 못한 것**: Linux x64/i386/AArch64, wasm32는 이 머신에 툴체인이 없어 push 시 CI로 확인한다. 결과를 이 로그에 덧붙인다.

*Starting point: after #3 merged the user asked for the next task, which design #1 names as phase 1's first: the census port, together with its prerequisite decoder. Zydis: the four files of rePIU's v4.1.1 amalgamation were copied with SHA-256 matching rePIU's notice, recorded in `THIRD_PARTY_NOTICES.md`, and built as the `rex86_zydis` STATIC target (`ZYDIS_STATIC_BUILD`, no warnings target), with C added to the project languages. Decoder: `src/decode/decoder.{h,cpp}` — `Decoder` fixed to 32-bit legacy mode and `DecodedInstruction` providing length, mnemonic and ISA-set names, the census-format operand signature, x87 and 80-bit-memory detection, the control-flow classification (direct/indirect jmp and call, jcc, ret, int, hlt) and the direct target via `ZydisCalcAbsoluteAddress`; the public contract is unchanged, Zydis types appear only in internal headers, and there is no consumer-adapter impact. Census: the logic in `census.{h,cpp}` and `rex86_census` in `main.cpp` (not built under Emscripten); recursive descent follows direct targets and fallthrough, continues through indirect calls and software interrupts on the premise that they return, and stops at ret, indirect jmp, hlt and decode failures; the linear sweep advances one byte on failure; the report prints the bounds, per-mnemonic counts and signatures, cumulative form coverage, the x87 tally and ISA sets; rePIU's long-mode measurements stayed behind as designed. Verification: two new test files (fifteen decoder forms plus failure paths; census reach, bound, range and empty-input cases), `rex86_unit_tests` checks 183 failures 0; the local Windows x86 MSVC Debug build (`-A Win32`, VS 18, warnings as errors) builds clean and passes `ctest` 2/2; `rex86_census` on a 17-byte synthetic binary prints `reached_instructions=7 sweep_decoded=7 sweep_failed=1 x87_total=1 x87_float80_memory=1` with the cumulative-coverage table. Not verified here: Linux x64/i386/AArch64 and wasm32 have no toolchain on this machine and are checked by CI on push, appended to this log. Documents: the census guide, the ARCHITECTURE rows marked implemented, and README's layout and attainment tables. Remaining: the real consumer-dump measurements are the user's follow-up recorded in `docs/analysis/` (as comments on this issue); the interpreter is the next task.*
