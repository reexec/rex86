## 2026-10-10

호스트: AMD Ryzen 5 5600X(Zen 3) 12 스레드, Linux, GCC 13, Clang 18, emsdk 3.1.74.

- **맥락 확인**: 내리기가 그대로 따를 인터프리터 코드를 읽었다. `access.cpp`의 `Linearize`/`ReadVirtual`/`WriteVirtual`(검사의 성공 조건), `ReadOperand`(즉값의 부호 확장, 읽고 쓰는 목적지의 `RequireWritable`), `Push`/`Pop`, `interpreter.cpp`의 ALU, INC/DEC, NEG, NOT, MOV, MOVZX/MOVSX, LEA, XCHG, 분기, `exec_arith.cpp`의 시프트와 IMUL, `exec_post386.cpp`의 CMOV.
- **인터프리터 쪽 변경**(동작 변화 없음): `FeatureEnabled`와 `Fetch`를 익명 namespace에서 꺼내 `interp/interpreter.h`에 선언했다. 프런트엔드가 같은 기능 판정과 같은 인출을 쓰게 해 x86 의미를 두 곳에 쓰지 않는다.
- **구현**:
  - `src/translate/ir/`의 `ir`, `evaluator`, `frontend`, `optimize`(설계 결정 1~6).
  - `src/tools/irdiff/`의 `rex86_irdiff_lib`과 `rex86_irdiff`. ctest에 `rex86_irdiff_smoke`(2만 건)를 등록했다.
  - `tests/unit/ir_test.cpp`: 형태별 차등 1만 건, 블록 차등 2,000건, 첫 범위의 mnemonic 37개가 모두 비교되는지, 검사 탈출(읽기 전용, `kTranslated`, 메모리 밖), 블록 형성(게이트, 인출 불가, 페이지 둘, 평탄하지 않은 CS, 다루지 않는 명령, CMOV 끔), ESP 기반 PUSH/POP 주소, 최적화.
- **구현 중에 고친 것**:
  - 개수 0인 시프트의 메모리 목적지: 인터프리터는 읽기 전에 쓰기 가능 여부를 본다. 읽기 검사만 두면 읽기 전용 세그먼트에서 결과가 갈린다. 쓰기 검사로 바꿨다(더 엄격해도 탈출이 맞게 처리한다).
  - D0/D1 형태의 개수 1은 Zydis가 visible로 세지 않을 수 있어 `operand_count`로 판정한다.
  - SETcc와 CMOVcc는 mnemonic 범위 대신 목록으로 판정한다. 범위로 하면 CET의 `SETSSBSY`가 사이에 낀다.
  - 최적화 테스트의 코드 뒤 0바이트가 `add [eax], al`(다루는 명령)이라 블록이 이어졌다. 테스트 코드 뒤에 HLT를 두었다.
- **차등이 결함을 잡는지 확인**(변이 시험, Release, `rex86_irdiff --cases 20000`):

  | 넣은 결함 | 결과 |
  |---|---|
  | AF를 비트 4 대신 비트 3에서 읽음 | 형태별 불일치 1,040 |
  | 쓰기 검사에서 `kTranslated`를 보지 않음 | 형태별 불일치 168(페이지 속성 차이) |
  | 최적화가 `Check`를 탈출 지점으로 보지 않음 | 블록 불일치 1,605 |
  | POP m의 주소를 증가 전 ESP로 계산 | 처음엔 0. 생성기가 `8F /0`의 ESP 기반 SIB를 사례당 약 4×10⁻⁶로만 만들었다 |

  - 넷째 결과로 생성기를 고쳤다. 다루는 opcode 목록에서 고르고, ModRM은 SIB 쪽, SIB는 ESP base 쪽으로 치우치게 했다. 직접 만든 PUSH/POP `[esp+4]` 테스트도 더했다. 그 뒤 같은 결함이 형태별 2, 블록 4, 단위 테스트 실패 4로 잡혔다.
- **속도**: 처음 판은 Debug 단위 테스트가 2.1초에서 27초로 늘었다. 64 KiB 메모리를 바이트 단위로 비교한 것이 거의 모든 시간이었다. `memcmp`를 먼저 하고 채우기를 64비트 단위로 바꿔 3.6초가 됐다. Release `rex86_irdiff` 10만 건이 3.1초다.
- **빌드와 ctest**(`-Werror`): 8개 구성 모두 통과.
  - x86-64 Debug, Release, Clang Debug, ASan/UBSan 예열 0, Clang libFuzzer + ASan/UBSan: 각 8/8.
  - i386 Debug, Release: 각 9/9.
  - wasm32: 6/6, `rex86_probe` `result=ok`. IR 차등이 wasm32에서도 돈다.
  - 단위 checks 1,938(64비트), failures 0.

*Host: AMD Ryzen 5 5600X (Zen 3), 12 threads, Linux, GCC 13, Clang 18, emsdk 3.1.74. Context: read the interpreter code the lowering follows (`access.cpp`'s `Linearize`/`ReadVirtual`/`WriteVirtual` for the checks' success condition, `ReadOperand` for immediate sign extension and `RequireWritable` on read-modify-write destinations, `Push`/`Pop`, the ALU, INC/DEC, NEG, NOT, MOV, MOVZX/MOVSX, LEA, XCHG and branches in `interpreter.cpp`, shifts and IMUL in `exec_arith.cpp`, CMOV in `exec_post386.cpp`). Interpreter-side change, no behavior change: `FeatureEnabled` and `Fetch` came out of the anonymous namespace into `interp/interpreter.h`, so the frontend asks the same feature question and fetches the same way, with x86 semantics written once. Implemented: `ir`, `evaluator`, `frontend` and `optimize` under `src/translate/ir/` (design decisions 1 to 6); `rex86_irdiff_lib` and `rex86_irdiff` under `src/tools/irdiff/`, with `rex86_irdiff_smoke` (20,000 cases) in ctest; `tests/unit/ir_test.cpp` with 10,000 per-form and 2,000 block differential cases, all 37 first-coverage mnemonics compared, check exits (read-only, `kTranslated`, outside memory), block formation (gate, unfetchable, two pages, non-flat CS, uncovered instruction, CMOV off), ESP-based PUSH/POP addresses and optimization. Fixed during implementation: a count-0 shift to memory needs the write check, since the interpreter demands a writable segment before the read; the count 1 of the D0/D1 forms is judged by `operand_count`, Zydis possibly not counting it visible; SETcc and CMOVcc are judged by list rather than by mnemonic range, which CET's `SETSSBSY` interrupts; the optimization test's trailing zero bytes are `add [eax], al`, a covered instruction, so a HLT now ends its code. Checking that the differential catches defects (mutation tests above): AF read from bit 3 gave 1,040 per-form mismatches; no `kTranslated` in the write check gave 168 (page attribute difference); the optimizer not treating `Check` as an exit gave 1,605 block mismatches; computing POP m's address from the old ESP gave none at first, the generator producing `8F /0` with an ESP-based SIB at about 4×10⁻⁶ per case, so the generator now picks from the covered opcode list and biases ModRM toward SIB and SIB toward an ESP base, with directed PUSH/POP `[esp+4]` tests added, after which the same defect gave 2 per-form and 4 block mismatches and 4 unit failures. Speed: the first version took the Debug unit tests from 2.1 s to 27 s, nearly all of it byte-wise comparison of 64 KiB; `memcmp` first and 64-bit fills brought it to 3.6 s, and 100,000 cases of Release `rex86_irdiff` take 3.1 s. Builds and ctest with `-Werror`: all eight configurations pass (x86-64 Debug, Release, Clang Debug, ASan/UBSan at warm-up 0 and Clang libFuzzer with ASan/UBSan, 8/8 each; i386 Debug and Release, 9/9 each; wasm32 6/6 with `rex86_probe` `result=ok`, the IR differential running on wasm32 too); 1,938 unit checks on 64-bit hosts, zero failures. Long differential runs, sharded by `scripts/fuzz_campaign.sh`, in the table above: zero mismatches on x86-64 (8 × 5M per-form, 8 × 1.25M blocks, seeds 43000-43007) and i386 (4 × 2.5M, 4 × 625,000, seeds 43100-43103); about 76% of per-form cases were compared (the rest took a check exit), 78 mnemonics in all.*
