# rex86 v0.0.22

3단계(IR 번역)의 첫 판입니다. 게스트 블록을 공용 IR로 내리고, 검증용 IR 평가기와 wasm 백엔드로 실행합니다. 번역은 기본으로 꺼져 있어, 아무것도 하지 않는 소비자의 동작은 그대로입니다. wasm32에서 번역을 켜면 인터프리터 대비 alu 워크로드가 7.8배, memory 5.2배, call 4.4배 빨라집니다.

## 변경 사항

- **설계**(#42): 기본 블록 단위 번역. 다루지 않는 명령, 실패한 메모리 검사(정확한 폴트), 번역 코드에 대한 store(SMC), 게이트 직전은 모두 "인터프리터 탈출" 하나로 처리합니다. 인터프리터가 정확성 기준으로 남습니다.
- **IR과 프런트엔드**(#43, `src/translate/ir/`):
  - 32비트 값, 명시적 레지스터·플래그 접근, 실패하면 인터프리터로 넘기는 메모리 검사, 블록 끝의 탈출로 된 IR입니다.
  - 프런트엔드는 평탄한 32비트 CS와 32비트 SS에서 정수 MOV, ALU, 상수 개수 시프트·회전, IMUL, PUSH/POP, 분기, SETcc, CMOVcc를 내립니다. 명령마다 모든 검사가 효과보다 먼저 옵니다.
  - 최적화(죽은 쓰기, 죽은 값 제거)와, IR의 의미를 정하는 이식 가능한 평가기가 있습니다.
- **번역 실행기**(#44, `src/translate/runtime`): 블록 머리의 진입 횟수로 계층화하고, 페이지 세대로 번역의 유효성을 봅니다. `Cpu::Run`이 기존 검사 뒤에 번역 블록을 실행합니다. 번역이 켜지면 인터프리터의 블록 루프가 분기 뒤에 돌아오는 판을 따로 씁니다. 꺼진 인터프리터의 비용은 그대로입니다.
- **wasm 백엔드**(#45, `src/translate/wasm/`): 블록 하나를 wasm 함수 하나로 만듭니다. 메모리 검사는 평가기와 같은 C++ 함수를 함수 테이블을 거쳐 부릅니다. 호스트가 모듈을 설치합니다.
- **웹 어댑터**(#45, `src/host/web/`, CMake `rex86_host_web`): `WasmModuleServices`의 동기 참조 구현과 Emscripten JS 라이브러리입니다. 코어 라이브러리 밖에 있습니다.
- **검증 도구**: IR 차등 `rex86_irdiff`(#43), 견고성 불변식 I8(번역 대 인터프리터, #44), CMake `REX86_FORCE_TRANSLATION`(`ON`은 평가기, `WASM`은 wasm), `rex86_int_fuzz --translate`(#46), 벤치마크 `--engine evaluator|wasm`과 엔진 메모리·번역 통계 줄.
- **CI와 캠페인**: CI에 번역 강제 작업 `linux-x64-translate`와 wasm32의 번역 강제 `WASM` 단계를 더했습니다. 릴리스 캠페인에 `irdiff-x64`, `wasm-translate`, `int-i386`의 `translate` 행을 더했습니다(#46).
- **규칙**(AGENTS.md): 새 브랜치는 `main`에서만 만들고, 작업 브랜치에는 새 이슈도 쌓습니다. 호스트 어댑터의 자리 `src/host/<호스트>/`를 정했습니다.

## 소비자 영향

- 공개 계약에는 추가만 있습니다.
  - `include/rex86/cpu.h`: `TranslationMode`(`kOff`, `kEvaluator`, `kWasm`), `TranslationOptions`(`mode`, `threshold`, `wasm`, `max_block_instructions`), `TranslationStats`, `Cpu::SetTranslation`(bool), `translation`, `translation_stats`, `CompleteWasmModule`, `FailWasmModule`, `SetDefaultTranslation`, `DefaultTranslation`.
  - `include/rex86/environment.h`: `WasmInstall`, `WasmModuleServices`.
- `Cpu`의 크기와 ABI가 바뀌었으므로 다시 빌드해야 합니다.
- 기본값은 꺼짐이라 동작은 바뀌지 않습니다. 웹 경로는 Worker에서 `rex86_host_web`을 링크하고 `SetTranslation({kWasm, 32, &adapter})`를 부르면 번역이 켜집니다. 링크에 `-sALLOW_TABLE_GROWTH`가 필요합니다(타깃이 실어 나릅니다).
- 이미 실행된 코드를 고치면 `InvalidateCode`를 불러야 한다는 계약(#34)이 번역에도 적용됩니다. 게이트 등록은 모든 번역을 버립니다.

- **견고성 I8**: 30만 건 위반 0.

## English

# rex86 v0.0.22

Phase 3's first version (IR translation): guest blocks are lowered to a shared IR and run by a verification IR evaluator and a wasm backend. Translation is off by default, so a consumer doing nothing sees unchanged behavior; with it on in wasm32, the alu workload runs 7.8 times as fast as the interpreter, memory 5.2 and call 4.4.

## Changes

- **Design** (#42): translation by basic blocks; uncovered instructions, failed memory checks (precise faults), stores into translated code (SMC) and the approach of a gate all take one "interpreter exit", the interpreter staying the correctness reference.
- **The IR and frontend** (#43, `src/translate/ir/`): an IR of 32-bit values with explicit register and flag access, memory checks that hand over to the interpreter on failure, and exits at the block end. The frontend lowers integer MOV, ALU, constant-count shifts and rotates, IMUL, PUSH/POP, branches, SETcc and CMOVcc under a flat 32-bit CS and a 32-bit SS, every check of an instruction before its effects. Optimization (dead writes and values) and a portable evaluator defining the IR's meaning.
- **The translation runtime** (#44, `src/translate/runtime`): tiering by block-head entry counts and translation validity by page generations; `Cpu::Run` runs translated blocks after its existing checks, and with translation on the interpreter's block loop uses a separate version returning after branches, the interpreter with translation off keeping its cost.
- **The wasm backend** (#45, `src/translate/wasm/`): a wasm function per block, memory checks calling the evaluator's own C++ function through the function table, the host installing the modules.
- **The web adapter** (#45, `src/host/web/`, CMake `rex86_host_web`): a synchronous reference `WasmModuleServices` and its Emscripten JS library, outside the core library.
- **Verification tools**: the IR differential `rex86_irdiff` (#43), robustness invariant I8 (translation against the interpreter, #44), CMake `REX86_FORCE_TRANSLATION` (`ON` for the evaluator, `WASM` for wasm), `rex86_int_fuzz --translate` (#46), and the benchmark's `--engine evaluator|wasm` with engine-memory and translation-count lines.
- **CI and campaign**: CI gains the forced-translation job `linux-x64-translate` and a forced-`WASM` step on wasm32; the release campaign gains `irdiff-x64`, `wasm-translate` and a `translate` row of `int-i386` (#46).
- **Rules** (AGENTS.md): new branches only from `main`, new issues stacking on a task branch; `src/host/<host>/` as the place of host adapters.

## Consumer impact

- The public contract only gains: in `include/rex86/cpu.h`, `TranslationMode` (`kOff`, `kEvaluator`, `kWasm`), `TranslationOptions` (`mode`, `threshold`, `wasm`, `max_block_instructions`), `TranslationStats`, `Cpu::SetTranslation` (bool), `translation`, `translation_stats`, `CompleteWasmModule`, `FailWasmModule`, `SetDefaultTranslation` and `DefaultTranslation`; in `include/rex86/environment.h`, `WasmInstall` and `WasmModuleServices`.
- `Cpu`'s size and ABI changed, so consumers must rebuild.
- The default is off, so behavior does not change. A web path turns translation on by linking `rex86_host_web` in its Worker and calling `SetTranslation({kWasm, 32, &adapter})`; linking needs `-sALLOW_TABLE_GROWTH`, which the target carries.
- The contract that changing already-run code requires `InvalidateCode` (#34) applies to translations, and registering a gate drops every translation.

## The previous release's campaign (v0.0.21)

The v0.0.21 tag was not pushed, so no campaign ran and there is no result to record. The same content (#40's verdict fix) is verified by this branch's smoke campaign and by this release's tag campaign.

## Validation

- **IR differential**: 40M per-form cases and 10M blocks on x86-64, 10M and 2.5M on i386, 1M on wasm32 (978,683 wasm runs) with 250,000 blocks, zero mismatches; every deliberate defect (flags, SMC, the optimization boundary, stack addressing, a wasm shift, parity) was caught.
- **Robustness I8**: 300,000 cases, zero violations.
- **The translated replay of the integer host comparison**: 10M cases on a Zen 3, zero mismatches.
- **Forced-translation builds**: ctest passes with the evaluator (x86-64 ASan/UBSan, i386) and with `WASM` (wasm32); single-step trace cases still run on the interpreter there because of the block length (#46's log).
- **Interpreter cost**: host instructions per step on the path with translation off fell (cachegrind, 3.9%).
- **Performance** (Node 24.19, AMD Ryzen 5 5600X, medians of three interleaved runs): wasm translation against the interpreter, alu 7.8 times (204.7 MIPS), memory 5.2, call 4.4, mixed 1.4; module installation averages 88 µs.
- **ctest** (`-Werror`): ten local configurations, CI on five hosts, the libFuzzer job and the 12-job smoke campaign are green.
