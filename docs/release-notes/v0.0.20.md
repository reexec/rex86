# rex86 v0.0.20

릴리스 tag를 push하면 GitHub Actions가 fuzz 캠페인을 돌립니다. 지금까지 작업 로그를 위해 로컬에서 돌리던 긴 검증(호스트 대조 fuzz, 견고성 하네스, libFuzzer, SingleStepTests)을 릴리스마다 같은 규모로 돌려 기록으로 남깁니다. 코어의 공개 계약은 바뀌지 않습니다.

## 변경 사항

- **fuzz 캠페인**(#37, `.github/workflows/fuzz-campaign.yml`, [가이드](../guides/fuzz-campaign.md)):
  - 실행 계기: tag `v*` push(전체 규모), Actions 탭의 "Run workflow"(규모와 시드 오프셋 선택), 캠페인 파일을 바꾼 브랜치 push(smoke).
  - 작업 8개: 정수 호스트 대조 i386(예열 기본값과 0, 각 2,000만 건), x87과 SIMD(1억, 1억, 2,000만 건), 견고성 하네스 x86-64 Release(100만), ASan/UBSan(10만), AArch64(50만), libFuzzer(그 구성의 ctest 뒤 30분), SingleStepTests/80386 real mode(941 파일). 전체 규모의 시간은 추정이며 첫 실행에서 재고 고칩니다.
  - 시드는 tag 버전 × 10^8을 도구별 기본 시드에 더합니다. tag 이름만으로 시드를 다시 계산할 수 있습니다.
  - 판정은 각 도구의 종료 코드입니다. 제조사 차이(`vendor_deviations`, 허용 사례)는 실패가 아니고, 러너 CPU 모델과 함께 작업 요약에 기록합니다.
  - `scripts/fuzz_campaign.sh`가 shard를 병렬로 돌리고 `[rex86-campaign]` 줄을 모읍니다. 로컬에서도 같게 씁니다.
- **브랜치 CI**(#37): `linux-x64-libfuzzer` 작업이 fuzz 전에 그 구성(Clang `-O2`, ASan/UBSan)의 ctest 전체를 돌립니다. 두 워크플로의 action을 Node.js 24 버전으로 올렸습니다(checkout v7, upload-artifact v7, cache v6, setup-emsdk v16). GitHub의 Node.js 20 사용 중단 경고가 사라집니다.
- **결함 수정**(#37, #32에서 발견): `GuestMemory`의 모든 접근자가 정수 주소 산술을 거칩니다. 정체 매핑(null base)에서 null 포인터 산술이라는 UB가 없어집니다. 32비트 호스트에서 실제 버퍼를 정체 매핑으로 읽고 쓰는 단위 테스트를 더했습니다. 성능은 그대로입니다.
- **머지 절차**(AGENTS.md): tag push 뒤 캠페인 결과를 확인합니다. 실패하면 tag를 지우거나 옮기지 않고 이슈를 만들어 patch 릴리스로 고칩니다. 다음 릴리스 노트에 앞 릴리스의 캠페인 결과를 적습니다.
- **문서**: #37의 설계, 지시서, 작업 로그, 가이드 `fuzz-campaign.md`, ARCHITECTURE의 CI 절, 개별 fuzz 가이드의 링크.

## 소비자 영향

- 공개 계약은 바뀌지 않습니다. `GuestMemory`의 수정은 결과를 바꾸지 않으며, 정체 매핑을 쓰는 32비트 소비자에게서 UB를 없앱니다.
- 소비자의 tag 올림은 캠페인이 녹색인 tag로만 합니다. 캠페인이 처음 도는 tag는 이 v0.0.20입니다(tag push는 그 tag가 가리키는 커밋의 워크플로를 쓰므로 v0.0.19에서는 돌지 않습니다).

## English

# rex86 v0.0.20

Pushing a release tag now runs a fuzz campaign on GitHub Actions. The long verification so far run locally for work logs (the host-comparison fuzzes, the robustness harness, libFuzzer, SingleStepTests) runs at the same scale for every release and stays on record. The core's public contract does not change.

## Changes

- **The fuzz campaign** (#37, `.github/workflows/fuzz-campaign.yml`, [guide](../guides/fuzz-campaign.md)):
  - Triggers: a `v*` tag push (full scale), "Run workflow" on the Actions tab (scale and seed offset chosen), and a branch push changing the campaign's files (smoke).
  - Eight jobs: the integer host comparison on i386 (default warm-up and 0, 20M cases each), x87 and SIMD (100M, 100M and 20M), the robustness harness in x86-64 Release (1M), under ASan/UBSan (100,000) and on AArch64 (500,000), libFuzzer (30 minutes after the ctest of its configuration), and SingleStepTests/80386 real mode (941 files). The full-scale times are estimates, measured and corrected at the first run.
  - Seeds add the tag's version × 10^8 to each tool's base seed, so they can be recomputed from the tag name alone.
  - The verdict is each tool's exit code. Vendor differences (`vendor_deviations`, tolerated cases) are not failures and are recorded in the job summary with the runner's CPU model.
  - `scripts/fuzz_campaign.sh` runs the shards in parallel and gathers `[rex86-campaign]` lines; it runs the same way locally.
- **Branch CI** (#37): the `linux-x64-libfuzzer` job runs the whole ctest of its configuration (Clang `-O2`, ASan/UBSan) before fuzzing. Both workflows move to the Node.js 24 versions of their actions (checkout v7, upload-artifact v7, cache v6, setup-emsdk v16), ending GitHub's Node.js 20 deprecation warning.
- **A defect fixed** (#37, found in #32): every `GuestMemory` accessor goes through integer address arithmetic, removing the UB of null-pointer arithmetic under the identity mapping (null base). A unit test reads and writes a real buffer through the identity mapping on 32-bit hosts. Performance is unchanged.
- **The merge procedure** (AGENTS.md): check the campaign after the tag push. A failing campaign never deletes or moves the tag; open an issue and fix it in a patch release. The next release notes record the previous release's campaign.
- **Documents**: the #37 design, work order and work log, the guide `fuzz-campaign.md`, ARCHITECTURE's CI section, links from the fuzz guides.

## Consumer impact

- The public contract does not change. The `GuestMemory` fix changes no result and removes UB for 32-bit consumers using the identity mapping.
- Consumers' tag bumps only take tags whose campaign is green. This v0.0.20 is the first tag to run the campaign (a tag push uses the workflows of the commit it points at, so v0.0.19 runs none).

The previous release, v0.0.19, is squash commit `3bdc6f7`. v0.0.19 had no campaign, so there is no campaign result to record.

## Validation

- **Smoke campaign**: runs 1 and 2 green in all nine jobs, with zero mismatches, violations and crashes; the runner CPU differed per job (AMD EPYC 7763, 9V45, 9V74).
- **The script**: one shard failing (exit code 1) and a missing binary (127) were checked locally to fail the job.
- **`GuestMemory`**: under Clang `-m32` UBSan the code before the fix fails the new test and passes after it; cachegrind's host instructions per step are unchanged.
- **Unit tests**: checks 1,866 (32-bit hosts), 1,850 (64-bit hosts), failures 0.
- **ctest** (`-Werror`): x86-64 Debug, ASan/UBSan and the Clang libFuzzer configuration 7/7; i386 Debug and Release 8/8; wasm32 5/5.
- CI on the five hosts and the libFuzzer job.
