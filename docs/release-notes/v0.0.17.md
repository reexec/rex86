# rex86 v0.0.17

README 목표 6(견고성과 격리)의 측정 수단을 갖췄습니다. 임의 바이트열과 임의 상태로 디코더와 인터프리터를 fuzz하는 하네스, libFuzzer 진입점과 CI 작업을 더했습니다. 코어는 바뀌지 않았습니다.

## 변경 사항

- **견고성 하네스** `rex86_robust`(`src/tools/robust/`):
  - 보호 구역으로 둘러싼 임의 게스트 메모리, 임의 페이지 속성, 임의 CPU 상태와 `Features`, 무작위로 답하는 `Environment`, `Run` 사이의 호스트 개입으로 코어를 돌립니다.
  - 확인하는 불변식:
    - 크래시가 없습니다.
    - `GuestMemory` 밖의 보호 구역이 바뀌지 않습니다. ASan 빌드에서는 보호 구역을 poison해 읽기도 잡습니다.
    - 쓰기 권한이 없는 페이지가 바뀌지 않습니다.
    - 페이지 속성은 `kTranslated`를 지우는 것 말고 바뀌지 않습니다.
    - `Run` 이벤트가 계약을 지킵니다.
    - 같은 케이스를 두 번 돌리면 결과가 같습니다.
  - 디코더 fuzz를 함께 돕니다.
  - 모든 호스트에서 빌드되고, 300건 smoke가 ctest(`rex86_robust_smoke`)로 모든 CI 작업에서 돕니다.
  - `--case`는 한 케이스의 Run마다 이벤트를 출력합니다.
- **libFuzzer**:
  - CMake 옵션 `REX86_LIBFUZZER`(Clang)가 `rex86_robust_libfuzzer`를 만듭니다.
  - 입력의 앞 16바이트가 생성기를, 나머지가 EIP의 코드를 정합니다.
  - 새 CI 작업 `linux-x64-libfuzzer`가 ASan/UBSan과 함께 60초 동안 돌고, 크래시 입력을 artifact로 남깁니다.
- **문서**:
  - #31 설계, 지시서, 작업 로그.
  - 가이드 `robustness-fuzz.md`, 분석 `robustness-fuzz.md`.
  - ARCHITECTURE, README 견고성 행(완료).

## 소비자 영향

- 공개 계약은 바뀌지 않았습니다.
- 하네스는 `REX86_BUILD_TESTS`가 꺼진 FetchContent 소비자에게 보이지 않습니다.
- 코어 결함은 발견되지 않았습니다.
- 발견 사항이 하나 있습니다. REP 문자열은 한 명령 안에서 끝까지 반복하므로, 큰 메모리에서는 명령 하나가 오래 걸릴 수 있습니다. 후속 #32에서 다룹니다.

## English

# rex86 v0.0.17

The instrument for README goal 6 (robustness and sandboxing): a harness fuzzing the decoder and interpreter with arbitrary bytes and state, a libFuzzer entry point and a CI job. The core is unchanged.

## Changes

- **The robustness harness** `rex86_robust` (`src/tools/robust/`):
  - Runs the core on arbitrary guest memory between guard zones, arbitrary page attributes, arbitrary CPU state and `Features`, a randomly answering `Environment` and host interventions between `Run`s.
  - The invariants it checks:
    - No crash.
    - The guard zones outside `GuestMemory` never change. Under ASan the zones are poisoned, so reads are caught too.
    - Pages without write permission never change.
    - Page attributes change only by `kTranslated` being cleared.
    - Every `Run` event keeps the contract.
    - The same case runs the same twice.
  - A decoder fuzz runs alongside.
  - Builds on every host; a 300-case smoke runs in every CI job through ctest (`rex86_robust_smoke`).
  - `--case` prints every Run's event of one case.
- **libFuzzer**:
  - The CMake option `REX86_LIBFUZZER` (Clang) builds `rex86_robust_libfuzzer`.
  - The first 16 input bytes drive the generator and the rest become the code at EIP.
  - The new CI job `linux-x64-libfuzzer` runs it for 60 seconds under ASan/UBSan and keeps crashing inputs as artifacts.
- **Documents**:
  - The #31 design, work order and work log.
  - The guide `robustness-fuzz.md` and the analysis `robustness-fuzz.md`.
  - ARCHITECTURE and README's robustness row (done).

## Consumer impact

- No contract change.
- The harness is invisible to a FetchContent consumer with `REX86_BUILD_TESTS` off.
- No core defect was found.
- One finding: a REP string runs to completion within one instruction, so one instruction can take long over large memory. Follow-up #32 handles it.
