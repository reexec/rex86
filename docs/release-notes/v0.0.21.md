# rex86 v0.0.21

정수 호스트 대조 fuzz의 판정을 고친 patch 릴리스입니다. v0.0.20 머지 때의 smoke 캠페인이 AMD Zen 5 러너에서 실패한 원인을 고쳤습니다. 코어와 공개 계약은 바뀌지 않습니다.

## 변경 사항

- **정수 fuzz의 제조사 차이 판정**(#40, `tests/host/linux/int_fuzz.cpp`):
  - Zen 5는 CMPS의 원본을 먼저 읽습니다. 원본 세그먼트가 null 선택자(i386 Linux 프로세스의 FS)라 원본이 #GP를 내고 목적지가 매핑 밖이면, Zen 5는 #GP를, 코어와 Intel, Zen 3은 목적지의 #PF를 냅니다. 기존 판정은 두 폴트가 모두 #PF인 경우만 다뤄 불일치로 셌습니다.
  - 새 판정 `SourceSegmentFirstCompareFault`는 CMPS이고, 호스트가 #GP이고, 원본 세그먼트가 null이고, 목적지가 매핑 밖이며, 기대값을 목적지 바이트의 #PF로 바꾸면 나머지가 모두 일치할 때만 `vendor_deviations`로 셉니다.
  - 코어의 목적지 먼저 순서는 그대로입니다(Intel, Zen 3, 386EX와 같음).
- **문서**: #40의 설계, 지시서, 작업 로그. 분석 `integer-host-comparison.md`의 절을 "Zen 5의 CMPS 읽기 순서"로 넓혔습니다. #37 작업 로그에 첫 전체 규모 캠페인의 실측을 더했습니다.

## English

# rex86 v0.0.21

A patch release fixing the integer host-comparison fuzz's verdict, the cause of the smoke campaign's failure on an AMD Zen 5 runner at the v0.0.20 merge. The core and the public contract do not change.

## Changes

- **The integer fuzz's vendor-deviation verdict** (#40, `tests/host/linux/int_fuzz.cpp`):
  - Zen 5 reads the CMPS source first. With the source segment a null selector (FS in an i386 Linux process) so that the source raises #GP, and the destination outside the mapping, Zen 5 raises #GP while the core, Intel and Zen 3 page-fault at the destination. The old verdict handled only two #PFs and counted this as a mismatch.
  - The new verdict `SourceSegmentFirstCompareFault` counts it under `vendor_deviations` only when it is a CMPS, the host raised #GP, the source segment is null, the destination lies outside the mapping, and everything else matches once the expectation reads as a #PF at a destination byte.
  - The core keeps its destination-first order (as Intel, Zen 3 and the 386EX).
- **Documents**: the #40 design, work order and work log; the analysis `integer-host-comparison.md` section widened to "Zen 5's CMPS read order"; the #37 work log gained the measurements of the first full-scale campaign.

## Consumer impact

None: only the host-comparison fuzz and documents change.

## Resolved issues

- [#40](https://github.com/reexec/rex86/issues/40) The integer fuzz does not judge Zen 5's CMPS source #GP as a vendor deviation : PR #41
