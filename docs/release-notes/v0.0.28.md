# rex86 v0.0.28

wasm 번역이 블록 여럿을 모듈 하나로 묶어 설치하고, 살아 있는 모듈 수에 예산을 둡니다([#49](https://github.com/reexec/rex86/issues/49)). Firefox는 한 프로세스에서 wasm 모듈을 16,349개까지만 설치하는데, 이 한도가 모듈 크기가 아니라 모듈 수에 걸린다는 것을 확인했습니다. 블록 16개씩 묶으면 같은 한도 안에서 블록 26만 개를 번역할 수 있습니다.

## 변경 사항

- **묶음 설치**: 문턱에 이른 블록은 대기열에 모였다가, 16개가 차거나 블록 진입이 4,096번 지나면 함수 여럿을 내보내는 모듈 하나로 설치됩니다. 대기 중인 블록은 인터프리터가 돌립니다. 비동기 설치(`kPending`)에서도 묶음 하나가 티켓 하나입니다.
- **모듈 수 예산**: 살아 있는 모듈이 4,096개(임시값, 4단계에서 확정)에 이르면 가장 오래된 모듈을 통째로 축출합니다. 축출된 블록은 다시 번역되기까지 문턱이 축출마다 2배씩, 최대 64배로 늡니다. 작업 집합이 예산보다 클 때 축출이 헛도는 것을 막기 위해서입니다.
- **공개 계약**: `TranslationOptions`에 `blocks_per_module`(16), `batch_wait`(4,096), `max_modules`(4,096), `TranslationStats`에 `modules_submitted`, `modules_evicted`를 더했습니다. 셋 모두 `kWasm`에만 적용됩니다.
- **도구**:
  - IR 차등은 wasm 비교를 블록 16개씩 모듈 하나로 설치합니다(`--wasm-batch`).
  - 벤치마크에 서로 다른 블록 24,576개를 도는 `blocks` 워크로드와 `--blocks-per-module`, `--batch-wait`, `--max-modules`, 모듈 보고 줄을 더했습니다. `mixed`는 이전과 같은 다섯 커널이라 버전 사이 비교가 그대로입니다.
  - 모듈 한도 탐침 `tests/host/web/module_limit.html`과 `drive.mjs --module-limit`. CI `browsers`에 탐침 단계를 더했고, Pages 사이트의 버전 디렉터리에도 올라갑니다.
- **브라우저 모음**: IR 차등을 5,000건에서 Node와 같은 2만 건으로 올렸고, 테스트 사이 기본 대기를 5초에서 1초로 줄였습니다.
- **문서**: #49 설계, 작업 지시서, 작업 로그, 기록 `browser-wasm.md` 3.1절, 브라우저 테스트 가이드(탐침, 실기기 Safari 한도 절차), ARCHITECTURE, README.

## 발견

- **Firefox의 한도는 모듈 수**: 함수를 1, 16, 64개 내보내는 모듈 모두 16,349개째에 실패했습니다. 모듈 크기는 wasm 32 KB까지 한도에 영향이 없었고, 51 KB에서는 8,220개였습니다. 실행 메모리 1 GiB를 64 KiB 단위로 나누는 것으로 추정합니다.
- **효과**: Firefox에서 `blocks`는 묶음 없이 모듈 16,339개 설치, 8,241개 거절, 0.34 MIPS였습니다. 기본값으로는 1,537개, 거절 0, 7.3 MIPS였습니다.
- **축출의 헛돌기**: 묶음 1, 예산 4,096에서 `blocks`는 모듈 76만 개를 설치하며 0.42 MIPS로 인터프리터(3.0)보다 느렸습니다. 축출 억제 뒤에는 11만 5천 개, 1.7 MIPS입니다. 기본값에서는 블록이 6만 5천 개를 넘어야 생기는 경우입니다.
- **IR 차등 도구의 결함**: 묶음 비교가 사례마다 바뀌는 CMOV 기능값을 묶음이 다 모인 뒤의 값으로 넘겨 불일치를 냈습니다. 생성 코드의 결함이 아니었고, 사례의 기능값을 함께 저장해 고쳤습니다.

## 소비자 영향

- 공개 계약에는 필드만 더해졌습니다. rePIU와 re2DJ의 어댑터는 고칠 것이 없습니다.
- 동작: wasm 번역이 켜진 웹 경로에서 블록이 문턱에 이른 뒤 설치까지 최대 블록 진입 4,096번을 더 기다립니다. 그 사이에는 인터프리터가 돕니다. 비동기 어댑터는 `Poll` 결과 하나에 블록이 여럿 들어옵니다.
- 이 tag의 캠페인이 녹색이면 두 소비자에 tag 올림 작업을 만듭니다.

## English

# rex86 v0.0.28

Wasm translation installs several blocks per module and puts a budget on live modules (#49). Firefox installs at most 16,349 wasm modules per process, and this release confirms the limit counts modules, not their size; with 16 blocks per module, 260,000 blocks fit within it.

## Changes

- **Batched installation**: blocks reaching the threshold gather in a queue and install as one module exporting several functions once 16 have gathered or 4,096 block entries have passed, the interpreter running them meanwhile; asynchronous installation (`kPending`) takes one ticket per batch.
- **Module count budget**: at 4,096 live modules (provisional, fixed in phase 4) the oldest module is evicted whole. An evicted block's threshold for translating again doubles per eviction, up to 64 times, so that a working set beyond the budget does not thrash.
- **Public contract**: `TranslationOptions` gains `blocks_per_module` (16), `batch_wait` (4,096) and `max_modules` (4,096), and `TranslationStats` gains `modules_submitted` and `modules_evicted`; all apply to `kWasm` alone.
- **Tools**:
  - The IR differential installs its wasm comparisons 16 blocks per module (`--wasm-batch`).
  - The benchmark gains the `blocks` workload of 24,576 distinct blocks, `--blocks-per-module`, `--batch-wait`, `--max-modules` and module report lines; `mixed` keeps its five kernels, so comparisons across versions hold.
  - The module limit probe `tests/host/web/module_limit.html` with `drive.mjs --module-limit`, as a step in CI's `browsers` and in each version directory of the Pages site.
- **Browser suite**: the IR differential rises from 5,000 to Node's 20,000 cases, and the default wait between tests drops from 5 seconds to 1.
- **Documents**: #49's design, work order and work log, record `browser-wasm.md` section 3.1, the browser test guide (the probe and the procedure for real-device Safari's limit), ARCHITECTURE and README.

## Findings

- **Firefox's limit counts modules**: modules exporting 1, 16 and 64 functions all failed at the 16,349th; module size did not matter up to 32 KB of wasm, while 51 KB modules stopped at 8,220. Inferred: 1 GiB of executable memory handed out in 64 KiB units.
- **Effect**: in Firefox, `blocks` installed 16,339 modules, refused 8,241 and ran at 0.34 MIPS without batching, and with the defaults installed 1,537, refused none and ran at 7.3.
- **Eviction thrashing**: with 1-block batches and a 4,096 budget, `blocks` installed 760,000 modules at 0.42 MIPS, slower than the interpreter (3.0); with the eviction backoff, 115,000 at 1.7 MIPS. With the defaults this takes more than 65,000 blocks.
- **An IR differential tool defect**: batched comparisons handed the interpreter the per-case CMOV feature as it stood after the batch had gathered, producing mismatches; the generated code was not at fault, and each case now stores its features.

## Consumer impact

- The public contract only gains fields; rePIU's and re2DJ's adapters need no change.
- Behavior: on web paths with wasm translation, a block waits up to 4,096 more block entries between reaching the threshold and its installation, the interpreter running it meanwhile; the asynchronous adapter delivers several blocks per `Poll` result.
- Once this tag's campaign is green, both consumers get tag-bump tasks.
