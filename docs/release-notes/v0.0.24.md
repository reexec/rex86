# rex86 v0.0.24

릴리스마다 그 빌드의 브라우저 테스트가 GitHub Pages(<https://reexec.github.io/rex86/>)에 올라갑니다. 휴대폰에서 빌드 없이 열 수 있고, 같은 기기에서 두 버전의 벤치마크를 비교할 수 있습니다. 코어와 공개 계약은 바뀌지 않습니다.

## 변경 사항

- **GitHub Pages 배포**(#52, `.github/workflows/pages.yml`):
  - `v*` tag를 push하면 그 tag를 브라우저용으로 빌드해 `/vX.Y.Z/`에 더합니다. 이전 버전은 그대로 남습니다.
  - 루트(버전 목록과 비교 페이지)는 배포된 최고 버전의 tag에서만 갱신됩니다.
  - `gh-pages` 브랜치는 배포마다 커밋 하나로 덮어써, 바이너리 이력이 쌓이지 않습니다.
  - 이미 있는 릴리스(v0.0.23 이상)는 수동 실행(`version` 입력)으로 채워 넣습니다.
  - 버전 하나가 약 9.4 MB입니다. 합이 500 MB를 넘으면 가장 오래된 버전부터 지웁니다.
- **버전 목록**: 버전마다 Benchmark(인터프리터와 wasm, 휴대폰 기본), Full suite(#48 모음 전체), 릴리스 노트 링크가 있습니다.
- **두 버전 비교**(`compare.html`):
  - 두 버전의 `rex86_bench`를 같은 기기에서 번갈아 돌립니다. 라운드마다 앞서는 버전을 바꿉니다.
  - 워크로드와 엔진마다 중앙값 MIPS와 B/A를 보여 줍니다. B/A는 ±5%를 넘고 두 쪽의 실행값이 겹치지 않을 때만 색으로 표시합니다. 기본은 5라운드입니다.
  - 각 실행이 보고한 버전이 고른 버전과 다르면 실패로 셉니다.
  - 결과는 `[rex86-compare]` 줄로 복사합니다.
- **도구**: 사이트 조립 스크립트 `scripts/pages_site.mjs`, 사이트 확인 드라이버 `tests/host/web/drive_pages.mjs`, 정적 서버의 `--site` 모드.
- **계약 주석**: 루트는 최신 tag에서, 버전 디렉터리는 각자의 tag에서 옵니다. 그래서 `worker.js`의 질의와 메시지, `rex86_bench`의 보고 줄을 앞으로도 유지할 계약으로 적었습니다.
- **CI**: `browsers` 작업이 조립한 사이트를 Chromium에서 확인합니다. 빌드가 보고하지 않는 버전 이름이 실패로 잡히는지도 봅니다.

## 발견

- 같은 빌드를 자기 자신과 비교해도(AMD Ryzen 5 5600X, 3라운드) 중앙값이 최대 14% 달랐습니다(Chromium wasm alu 0.862). 그래서 ±5% 경계만으로는 변화가 없는데도 색이 칠해집니다. 실행값이 겹치지 않는다는 조건과 5라운드 기본값의 근거입니다. 5라운드에서는 거짓 표시가 없었습니다([로그](../work-logs/20261011-i052-pages-browser-tests.md)).

## 소비자 영향

- v0.0.22부터의 [#50](https://github.com/reexec/rex86/issues/50) 결함(번역을 켠 경우의 I8 위반)은 아직 고쳐지지 않았습니다. v0.0.23 캠페인의 실패([#53](https://github.com/reexec/rex86/issues/53))도 열려 있습니다. 소비자의 tag 올림은 이 둘을 고친 patch 릴리스의 캠페인이 녹색이 된 뒤에 합니다.

## English

# rex86 v0.0.24

Every release's browser tests now go to GitHub Pages (https://reexec.github.io/rex86/), opened on a phone without a build, with a comparison of two versions' benchmarks on one device. Neither the core nor the public contract changes.

## Changes

- **GitHub Pages deployment** (#52, `.github/workflows/pages.yml`): a `v*` tag push builds that tag for browsers and adds it at `/vX.Y.Z/`, earlier versions staying; the root (the version list and the comparison) is refreshed only from the highest deployed version's tag; `gh-pages` is overwritten by one commit per deployment, so binaries do not pile up in history; existing releases (0.0.23 or later) are backfilled by a manual run with the `version` input; one version takes some 9.4 MB, the oldest dropped once the total passes 500 MB.
- **The version list**: per version, Benchmark (interpreter and wasm, the phone default), Full suite (#48's whole suite) and the release notes.
- **Comparing two versions** (`compare.html`): runs two versions' `rex86_bench` alternately on one device, the one going first swapping each round; shows median MIPS and B/A per workload and engine, colored only past ±5% when the two sides' runs do not overlap, five rounds by default; counts a run whose reported version differs from the chosen one as failed; copies results as `[rex86-compare]` lines.
- **Tools**: the site assembler `scripts/pages_site.mjs`, the site check driver `tests/host/web/drive_pages.mjs`, and the static server's `--site` mode.
- **Contract comments**: the root comes from the newest tag and each version directory from its own, so `worker.js`'s query and messages and `rex86_bench`'s report lines are written down as a contract to keep.
- **CI**: the `browsers` job checks an assembled site in Chromium, including that a version name the build does not report fails.

## Findings

- One build compared with itself (AMD Ryzen 5 5600X, three rounds) moved medians by up to 14% (Chromium wasm alu 0.862), so a ±5% bound alone colors changes that are not there; that grounds the no-overlap condition and the five-round default, which marked nothing falsely (log).

## Consumer impact

- Neither the public contract (`include/rex86/`) nor the core changes.
- #50's defect from v0.0.22 on (an I8 violation with translation on) is not fixed yet, and v0.0.23's campaign failure (#53) is open; consumers' tag bumps wait for the patch release fixing both and its green campaign.

## The previous release's campaign (v0.0.23)

Run 38069279391: **failed**; eight of twelve jobs passed and four failed.

- **int-i386** (host-comparison fuzz, three configurations, 20M cases each): five CMPS fault kind mismatches on an AMD EPYC 9V45 (four `cmpsd`, one `cmpsw`, FS prefix, the host raising #GP), and two shards ending in a segfault (exit code 139) with no output, one in the translate configuration on an AMD EPYC 9V45 and one in `warmup-0` on an Intel Xeon 6973P-C; cause unresolved, filed as #53.

## Validation

- **The site** (locally, Chromium 153 and Firefox 155): the version list, a version page's benchmark and a version compared with itself (`result=ok`) pass; comparing a version name the build does not report fails as expected (`result=fail`).
- **A/A** (AMD Ryzen 5 5600X, the default 20 frames, five rounds): all four rows past ±5% overlapped, and no row was colored.
- **The assembler**: keeps the root on a lower backfill, refreshes it from a higher tag, removes the oldest versions past the budget, and refuses versions before 0.0.23 and malformed ones.
- **The existing runner**: `drive.mjs` over the generalized server passes the unit tests, traces, benchmark smoke and the asynchronous test.
- **Workflows**: actionlint 1.7.12 reports nothing; the actual deployment first runs on this tag's push.
