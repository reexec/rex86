# rex86 v0.0.34

첫 소비자 통합을 위한 계약 두 가지를 더합니다. rePIU의 `emulated` 실행 모델([reexec/rePIU#61](https://github.com/reexec/rePIU/issues/61))이 이 둘로 원본 게임(pumpitea)을 rex86 위에서 타이틀 화면과 데모 플레이까지 실행합니다. 두 옵션 모두 기본값이 꺼짐이라, 켜지 않은 소비자의 동작은 바뀌지 않습니다.

## 변경 사항

- **사용자 모드 특권 의미**([#69](https://github.com/reexec/rex86/issues/69)): `Features::user_mode`. 켜면 코어가 CPL 3, IOPL 0, IDT 게이트 DPL 0인 프로세스처럼 동작합니다. CLI, STI, HLT, IN, OUT, INS, OUTS는 실행 전 `kPrivilegedInstruction`, `INT imm8`은 실행 전 `kGeneralProtection`(오류 코드 벡터×8+2)입니다. POPF와 IRET는 IF와 IOPL을 바꾸지 않습니다. INT3, INTO, INT1은 그대로입니다. Win32 사용자 모드 프로세스가 폴트를 내는 바로 그 자리에서 멈추게 하려는 것입니다.
- **호스트 경계 명령**([#70](https://github.com/reexec/rex86/issues/70)): `Features::host_boundaries`, `Environment::IsHostBoundary(bytes, length)`, `StopReason::kHostBoundary`, `Cpu::SkipHostBoundaryOnce()`. 켜면 명령을 실행하기 전에 호스트에 묻습니다(디코드마다 한 번, 답은 디코드 캐시에 저장). 경계면 실행하지 않고 멈춥니다. 호스트가 처리하지 않기로 하면 한 번 그대로 실행합니다. 번역 블록은 경계 앞에서 끝납니다.
- **도구**: `StopReason`를 switch하는 bench와 probe에 새 값을 더했습니다(GCC `-Wswitch`).
- **시험**: `user_mode_test.cpp`(명령마다 실행 전 폴트와 상태 불변, POPF/IRETD 마스크, 꺼짐 기본값, 번역 경로), `host_boundary_test.cpp`(멈춤, 한 번 건너뛰기와 EIP가 바뀌면 무효, 디코드당 한 번 질의, 번역 경로).
- **문서**: #69, #70의 설계, 작업 지시서, 작업 로그. README 달성도 표의 2A 행.

## 소비자 영향

## English

# rex86 v0.0.34

Two contract additions for the first consumer integration. With them, rePIU's `emulated` execution model ([reexec/rePIU#61](https://github.com/reexec/rePIU/issues/61)) runs an original game (pumpitea) on rex86 to its title screen and demo play. Both options are off by default, so a consumer that does not turn them on sees no change.

## Changes

- **User-mode privilege semantics** (#69): `Features::user_mode`. When on, the core behaves as a process at CPL 3 with IOPL 0 and DPL 0 IDT gates: CLI, STI, HLT, IN, OUT, INS and OUTS raise `kPrivilegedInstruction` and `INT imm8` raises `kGeneralProtection` (error code vector×8+2), all before retiring; POPF and IRET leave IF and IOPL alone; INT3, INTO and INT1 are unchanged. It makes the core stop exactly where a Win32 user-mode process faults.
- **Host boundary instructions** (#70): `Features::host_boundaries`, `Environment::IsHostBoundary(bytes, length)`, `StopReason::kHostBoundary`, `Cpu::SkipHostBoundaryOnce()`. When on, the host is asked before an instruction runs (once per decode, the answer kept in the decode cache) and a boundary stops the core unexecuted; one the host chooses not to handle runs once as it is. Translated blocks end before boundaries.
- **Tools**: the bench and probe switches over `StopReason` gain the new value (GCC `-Wswitch`).
- **Tests**: `user_mode_test.cpp` (each instruction faulting before retiring with the state intact, the POPF/IRETD masks, the default off, the translation path) and `host_boundary_test.cpp` (the stop, skipping once and its lapse when EIP moves, one question per decode, the translation path).
- **Documents**: the designs, work orders and work logs of #69 and #70; the README attainment table's 2A row.

## Consumer impact

- **rePIU**: the `emulated` execution model turns both options on; its adapter lives in rePIU, which bumps its tag to this release.
- **re2DJ**: unaffected (off by default). Its guests are Win32, so it can use `user_mode` the same way.

## Resolved issues

- #69 User-mode privilege semantics (CPL 3, IOPL 0): Features::user_mode
- #70 Host boundary instructions: Environment::IsHostBoundary and StopReason::kHostBoundary
