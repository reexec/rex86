# rex86 v0.0.15

벤치마크 하네스 `rex86_bench`를 더하고 인터프리터의 첫 성능 기준선을 기록했습니다. 코어는 바뀌지 않았습니다.

## 변경 사항

- **벤치마크 하네스** `src/tools/bench/`:
  - 바이트 어셈블러가 실행 중에 합성 워크로드 여섯을 조립합니다: `alu`, `memory`, `call`, `string`, `x87`, 그리고 다섯을 차례로 부르는 `mixed`.
  - 코어는 공개 계약만으로 프레임 단위로 돕니다. 한 프레임은 `Run(budget)` 한 번이고, 프레임마다 정확히 예산만큼 retire합니다.
  - 매 바퀴의 결과를 C++ 참조 모델과 대조합니다. 틀린 결과는 성능으로 치지 않습니다.
  - 보고: MIPS, 프레임 시간 p50/p99/최대, 첫 프레임까지의 시간, 기판 넷(EZ2DJ 1세대, MK3, MK5, EZ2DJ 2세대) 대비 실시간 비율. 출력은 probe와 같은 `key=value` 줄입니다.
  - 옵션: `--frames`, `--budget`, `--ipc`, `--only`, `--engine`, `--smoke`, `--dump`. 번역 백엔드가 없으므로 `--engine translator`는 `engine_available=false`로 거절합니다.
- **빌드**: `rex86_bench_lib`, `rex86_bench`(모든 호스트, wasm32는 `-sNODERAWFS`), ctest `rex86_bench_smoke`, `windows-x86-release` 빌드와 테스트 프리셋.
- **단위 테스트** `tests/unit/bench_test.cpp`: 인코딩 44종을 코어 디코더로 확인, 분기 고정, 워크로드 검증, 프레임 분할, 백분위.
- **정수 fuzz의 제조사 이탈(#22 후속)**: CI 러너 AMD EPYC 9V45(Zen 5)는 CMPS의 두 피연산자가 모두 닿을 수 없을 때 원본 DS:(E)SI 주소를 보고합니다. Intel과 AMD Zen 3은 목적지 ES:(E)DI 주소를 보고하고 코어도 그렇습니다. AMD Zen 3의 긴 실행에서는 BOUND가 비교 전에 두 경계를 모두 읽어, 상한이 닿을 수 없으면 #BR 대신 페이지 폴트를 낸다는 것도 드러났습니다(250만 건 중 32건). fuzz는 두 경우를 좁은 조건으로 `vendor_deviations`에 따로 세고 trace에 기록하지 않습니다. 코어는 바뀌지 않았습니다.
- **문서**: #27 설계, 지시서, 작업 로그, 가이드 `docs/guides/benchmark.md`, 분석 `docs/analysis/interpreter-performance.md`, ARCHITECTURE, README 달성도와 현재 수치.

## English

# rex86 v0.0.15

Adds the benchmark harness `rex86_bench` and records the interpreter's first performance baseline. The core is unchanged.

## Changes

- **Benchmark harness** `src/tools/bench/`:
  - A byte assembler builds six synthetic workloads at run time: `alu`, `memory`, `call`, `string`, `x87`, and `mixed`, which calls the five in turn.
  - The core runs through the public contract alone, frame by frame. A frame is one `Run(budget)` and retires exactly the budget.
  - Every lap's result is checked against a C++ reference model. A wrong result never counts as performance.
  - Reports: MIPS, frame-time p50/p99/max, time to first frame and the real-time ratio against the four boards (EZ2DJ generations 1 and 2, MK3, MK5), as `key=value` lines like the probe's.
  - Options: `--frames`, `--budget`, `--ipc`, `--only`, `--engine`, `--smoke`, `--dump`. No translation backend exists yet, so `--engine translator` is refused with `engine_available=false`.
- **Build**: `rex86_bench_lib`, `rex86_bench` (every host, `-sNODERAWFS` on wasm32), the ctest entry `rex86_bench_smoke`, and the `windows-x86-release` build and test presets.
- **Unit tests** `tests/unit/bench_test.cpp`: 44 encodings checked through the core's decoder, branch fixups, workload verification, frame slicing and percentiles.
- **Integer fuzz vendor deviation (#22 follow-up)**: the CI runner's AMD EPYC 9V45 (Zen 5) reports the source DS:(E)SI address when both CMPS operands are unreachable, where Intel, AMD Zen 3 and the core report the destination ES:(E)DI. A long run on an AMD Zen 3 also showed BOUND reading both bounds before comparing, so it page-faults instead of raising #BR when the upper bound is unreachable (32 cases in 2.5M). The fuzz counts both cases apart under `vendor_deviations`, on narrow conditions, and keeps them out of traces. The core is unchanged.
- **Documents**: the #27 design, work order and work log, the guide `docs/guides/benchmark.md`, the analysis `docs/analysis/interpreter-performance.md`, ARCHITECTURE, README attainment and current figures.

## Baseline

AMD Ryzen 5 5600X, Release, otherwise idle:

| Build | mixed MIPS | Range without string |
|---|---|---|
| x86-64 GCC 13 | 3.57 | 3.7 - 4.5 |
| Windows x86 MSVC 19.50 | 2.23 | 2.0 - 2.4 |

At an assumed (inferred) IPC of 1.0, the real-time ratio is about 0.009 for the 400 MHz boards and about 0.0026 for the 1.4 GHz board.

## Consumer impact

- No contract change.
- The harness is invisible to a FetchContent consumer with `REX86_BUILD_TESTS` off.
