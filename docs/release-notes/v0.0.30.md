# rex86 v0.0.30

브라우저에서 바로 실행되는 웹 데모 페이지를 더했습니다([#62](https://github.com/reexec/rex86/issues/62), README 목표 5). 페이지를 열면 wasm으로 빌드한 코어가 합성 x86 워크로드를 실행하고, 엔진 선택, retire 수, 처리량, 검증 상태를 실시간으로 보여 줍니다. 이 릴리스부터 GitHub Pages의 **Run the demo**로 열 수 있습니다.

## 변경 사항

- **데모 엔진 `rex86_demo`**: Emscripten에서만 빌드하는 모듈 팩토리(`createRex86Demo`)입니다. 벤치마크의 `bench::Machine`을 프레임 단위로 부르는 C 함수 여섯(`rex86_demo_info`, `_start`, `_frame`, `_stat`, `_failure`, `_stop`)을 냅니다.
  - 데모의 프레임은 `rex86_bench`의 프레임과 같습니다. 그래서 같은 페이지에서 벤치마크 수치를 재현합니다.
  - 바퀴마다 C++ 참조 모델과 맞춰 보고, 틀리면 멈추고 이유를 보입니다.
- **데모 페이지** `demo.html`, `demo.js`, `demo_worker.js`: Worker가 코어를 돌리고 페이지는 그립니다.
  - 워크로드 여덟, 엔진 셋(인터프리터, wasm, 평가기), 프레임당 단계 수를 고릅니다.
  - MIPS(최근 1초, 시작 이후)와 그래프, retire 수, 검증된 바퀴, 번역 비율을 보입니다. 번역 통계, 메모리와 코어 모듈 크기(목표 7의 계측), 대상 기판 넷 기준 실시간 비율도 보입니다.
  - **Measure**는 모든 워크로드를 벤치마크와 같은 조건으로 잽니다. **Copy report**는 `[rex86-demo]` 줄을 복사합니다.
- **배포**: Pages의 버전 디렉터리마다 데모가 올라갑니다. `versions.json` 항목에 `demo` 표시가 붙고, 루트 목록이 **Run the demo**와 버전별 **Demo**로 링크합니다.
- **검증 도구**:
  - Node ctest `rex86_demo_smoke`(`demo_smoke.cjs`): 모든 엔진과 워크로드.
  - `drive_demo.mjs`: CI `browsers`에서 Chromium, Firefox, WebKit.
  - `drive_pages.mjs`: 버전의 데모가 돌고 루트가 링크하는지 봅니다.
- **문서**: #62 설계, 작업 지시서, 작업 로그, 브라우저 테스트 가이드 5절(웹 데모, 실기기 보고 절차), README 목표 5와 달성도, ARCHITECTURE.

## 발견

- 코어 모듈(데모 엔진)은 522 KiB, 실행 중 wasm 힙은 약 16 MiB입니다(벤치마크 게스트 4 MiB 포함).
- 짧은 실행의 앞 프레임은 번역과 모듈 설치가 섞여 느립니다. 가이드는 그래프가 평평해진 뒤 읽도록 안내합니다.
- Firefox의 Worker에서는 `performance.now()`가 1 ms 단위로 거칠어(교차 출처 격리 없음), 짧은 프레임의 시간이 정수로 보입니다.

## 소비자 영향

없습니다. 코어와 공개 계약은 바뀌지 않았습니다. 새 타깃 `rex86_demo`는 시험 도구 구성의 Emscripten 빌드에만 생깁니다.

## English

# rex86 v0.0.30

A web demo page runs in the browser (#62, README goal 5): opening it runs the wasm-built core on synthetic x86 workloads and shows the engine choice, retired counts, throughput and verification live. From this release it opens from **Run the demo** on GitHub Pages.

## Changes

- **The demo engine `rex86_demo`**: a module factory built by Emscripten alone (`createRex86Demo`), exporting six C functions (`rex86_demo_info`, `_start`, `_frame`, `_stat`, `_failure`, `_stop`) that drive the benchmark's `bench::Machine` frame by frame.
  - A demo frame is a `rex86_bench` frame, so the page reproduces the benchmark figures.
  - Each lap is checked against the C++ reference model, and a wrong one stops the run with the reason.
- **The demo page** `demo.html`, `demo.js` and `demo_worker.js`: a Worker runs the core and the page draws.
  - Pick one of eight workloads, one of three engines (interpreter, wasm, evaluator) and the steps per frame.
  - It shows MIPS (the last second and since start) with a graph, retired steps, verified laps and the share run translated, plus translation statistics, memory and the core module's size (goal 7's instrumentation) and real-time ratios against the four target boards.
  - **Measure** runs every workload as the benchmark does; **Copy report** copies `[rex86-demo]` lines.
- **Deployment**: each Pages version directory carries the demo; `versions.json` entries gain a `demo` mark, and the root list links **Run the demo** and a **Demo** per version.
- **Verification tools**:
  - The Node ctest `rex86_demo_smoke` (`demo_smoke.cjs`), over every engine and workload.
  - `drive_demo.mjs` in CI `browsers`, in Chromium, Firefox and WebKit.
  - `drive_pages.mjs` checks that a version's demo runs and the root links it.
- **Documents**: #62's design, work order and work log, section 5 of the browser test guide (the web demo and the real-device report procedure), README goal 5 and attainment, and ARCHITECTURE.

## Findings

- The core module (the demo engine) is 522 KiB and the wasm heap while running about 16 MiB (the benchmark's 4 MiB guest included).
- A short run's first frames mix translation and module installation and run slow; the guide says to read the figures once the graph levels.
- In Firefox's Worker, `performance.now()` is coarsened to 1 ms (no cross-origin isolation), so short frames show whole-number times.

## Consumer impact

None: the core and the public contract do not change; the new target `rex86_demo` appears only in Emscripten builds of the test tool configuration.

## The previous release's campaign (v0.0.29)

Run 38354150065: **success**, all 12 jobs passing, the first full-scale campaign on Ubuntu 26.04 runners.
- The three int-i386 jobs (4 × 5M cases each) had zero mismatches, warmup-default and translate on AMD EPYC 7763 and warmup-0 on AMD EPYC 9V74.
- x87-x64 (4 × 25M), simd-x64 (4 × 25M) and simd-i386 (4 × 5M) had zero mismatches on a newly seen Intel Xeon Platinum 8573C.
- Robustness had zero violations: robust-release (AMD EPYC 9V74, 4 × 250,000), robust-asan (AMD EPYC 9V45, 4 × 25,000), robust-arm64 (Neoverse-N2, 4 × 125,000) and robust-wasm (4 × 50,000). The slowest robust-asan shard took about 650 seconds, and the new watchdog (60 seconds a case) raised no false alarm.
- irdiff-x64 (4 × 5M), irdiff-wasm (4 × 500,000), SST (some 1.74M tests) and libFuzzer (1,821 seconds) all passed.

## Validation

- **Node** (emsdk 6.0.8, Node 24.19.0): `rex86_demo_smoke` verified three engines × eight workloads and refused an unknown workload.
- **Browsers** (local, Playwright 1.63.0's Chromium 153 and Firefox 155): `drive_demo.mjs`'s live runs and measurement passed, and `drive_pages.mjs` on an assembled site passed with `check=demo`; the page was checked at 1,100 px in the light theme and 390 px in the dark one.
- **CI**: every job green; the `browsers` job's web demo step passed in Chromium, Firefox and WebKit, as did the wasm32 job's `rex86_demo_smoke` (emsdk 3.1.74) and the Pages smoke's demo check.
