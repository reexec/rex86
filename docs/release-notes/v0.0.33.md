# rex86 v0.0.33

자기 시작으로 돌아가는 번역 블록(한 블록짜리 고리)을 생성된 wasm 안에서 반복합니다([#67](https://github.com/reexec/rex86/issues/67)). 블록 전환을 세어 보니 alu와 memory는 99.9%가 이런 전환이었습니다. 디스패치를 거치지 않게 되어 v0.0.32보다 alu가 63%, memory가 38% 빨라졌습니다.

## 변경 사항

- **제자리 반복**: 자기 시작으로 가는 탈출이 있는 블록은 본체를 wasm `loop`로 감쌉니다. 그 탈출에서 다음 반복 전체가 허용된 단계 안이고 주의 신호(정지 요청, 대기 인터럽트)가 꺼져 있으면 되돌아갑니다. 아니면 지금처럼 탈출합니다. 다른 탈출은 앞선 반복의 단계를 함께 보고합니다. 멈추는 단계와 결과는 반복마다 디스패치한 것과 같습니다.
- **실행 제한**: `Backend::Run`과 `Translator::Run`이 `RunLimits`(최대 단계, 주의 신호)를 받습니다. `Cpu`는 `min(남은 예산, 2^30)`을 넘깁니다. `ExitResult::loops`가 제자리 반복 수를 돌려주고, `TranslationStats::block_runs`는 반복을 포함해 셉니다.
- **문맥**: 생성 코드가 읽는 구조체가 `CheckContext`에서 `RunContext`로 넓어졌습니다. 최대 단계, 주의 신호 주소, 반복 수가 더해졌습니다.
- **wasm 작성기**: `loop`, `br`, `i32.le_u`.
- **IR 차등**: wasm 블록을 평가기와 한 번씩 비교하도록 한 번만 돌립니다.
- **시험**: `WasmLoopTests`가 고리 프로그램을 예산 1, 3, 7, 50, 100만 단계로 잘라 매번 인터프리터와 비교합니다. 대기 인터럽트로 주의 신호가 켜진 채로도 비교합니다.
- **문서**: #67 설계, 작업 지시서, 작업 로그, [인터프리터 성능 분석](../analysis/interpreter-performance.md) 2.7절, ARCHITECTURE.

## 발견

- **블록 전환**(네이티브 평가기): 자기 시작으로 가는 비율은 alu 99.9%, memory 99.9%, mixed 55%, call 0%(CALL과 RET), blocks 0%(정적 점프)입니다.
- **결과**(v0.0.32와 번갈아 일곱 번 최고값, wasm, 측정 기계에 다른 부하 있음): alu 59.9 → 97.8(+63%), memory 44.2 → 60.8(+38%). call, blocks, mixed는 변동 안입니다.
- **다음**: call과 blocks는 다른 블록으로 갑니다. 블록 연결에는 모듈 간 간접 호출, 스택 깊이(tail call 지원), RET 같은 동적 목적지가 걸려 있어 따로 설계합니다.

## 소비자 영향

## English

# rex86 v0.0.33

Translated blocks that go back to their own start (one-block loops) now repeat inside the generated wasm (#67). Counting block transitions showed 99.9% of alu's and memory's to be of this kind; with dispatch out of the way, alu runs 63% and memory 38% faster than v0.0.32.

## Changes

- **Passes in place**: a block with an exit to its own start has its body wrapped in a wasm `loop`; at that exit it goes back when another whole pass fits the steps allowed and attention (a stop request, a pending interrupt) is clear, and exits as before otherwise. Other exits report the earlier passes' steps as well. Stop points and results equal dispatching every pass.
- **Run limits**: `Backend::Run` and `Translator::Run` take `RunLimits` (most steps, attention), the `Cpu` passing `min(remaining budget, 2^30)`; `ExitResult::loops` returns the passes run in place, and `TranslationStats::block_runs` counts them.
- **Context**: the structure generated code reads grew from `CheckContext` into `RunContext`, adding the most steps, the attention address and the pass count.
- **Wasm writer**: `loop`, `br`, `i32.le_u`.
- **IR differential**: wasm blocks run one pass, to be compared with the evaluator pass by pass.
- **Tests**: `WasmLoopTests` runs a loop program with the budget cut into slices of 1, 3, 7, 50 and a million steps, comparing with the interpreter every time, and again with attention raised by a pending interrupt.
- **Documents**: #67's design, work order and work log, section 2.7 of the interpreter performance analysis, and ARCHITECTURE.

## Findings

- **Block transitions** (native evaluator): the share going back to the block's own start is 99.9% on alu and memory, 55% on mixed, and 0% on call (CALL and RET) and blocks (static jumps).
- **Results** (the best of seven interleaved with v0.0.32, wasm, with other load on the measuring machine): alu 59.9 to 97.8 (+63%), memory 44.2 to 60.8 (+38%), and call, blocks and mixed within the variation.
- **Next**: call and blocks go to other blocks; linking them involves indirect calls across modules, stack depth (tail-call support) and dynamic targets such as RET, so it is designed separately.

## Consumer impact

None: the public contract and results stay, and consumers' one-block loops run without dispatch when translation is on.
