# rex86 v0.0.29

작은 후속 정리([#59](https://github.com/reexec/rex86/issues/59))와 #49의 후속([#60](https://github.com/reexec/rex86/issues/60))을 담았습니다. 코드가 바뀐 블록의 재번역을 억제하고, 견고성 하네스에 시간 감시를 두고, 비교 페이지가 같은 세션의 A/A를 함께 돌립니다. CI는 Ubuntu 26.04 러너로 옮겼습니다.

## 변경 사항

- **재번역 억제**(#60):
  - 블록 진입은 머리 페이지의 코드가 그대로인 동안만 셉니다. 쓰기가 문턱보다 잦은 페이지의 블록은 번역되지 않습니다.
  - 코드가 바뀌어 번역(대기 중 포함)이 버려지면, 다시 번역하기까지 진입이 문턱의 2배, 4배, … 최대 64배 필요합니다. #49의 축출 억제와 같은 횟수(`backoff`)를 씁니다.
  - 공개 계약 `TranslationStats`에 `blocks_invalidated`를 더했습니다. 코드가 바뀌어 버려진 번역의 수입니다.
- **벤치마크**: 자기 코드 페이지에 쓰는 `smc` 워크로드를 더했습니다(#60). 반복마다 페이지 안의 변수에 쓰고, 16번째마다 ADD의 즉치값을 고칩니다. `mixed`에는 넣지 않아 버전 사이 비교가 그대로입니다. 번역 엔진의 `modules_submitted=` 줄에 `blocks_invalidated=`가 붙습니다.
- **견고성 하네스의 시간 감시**(#59): 케이스 하나가 60초를 넘기면 `VIOLATION seed=<S>: watchdog: ...`를 적고 실패로 끝냅니다. 상한은 `--case-seconds N`(0이면 끔)입니다. 스레드가 없는 wasm32 빌드에는 없습니다.
- **비교 페이지의 A/A 대조**(#59): `compare.html`이 A를 한 번 더(A2) 돌리고 A2/A 열을 보입니다. 기본으로 켜지며, 실행이 1.5배가 됩니다.
  - A2/A가 표시 규칙에 걸린 행은 unsteady로 보입니다.
  - B/A는 A2/A보다 1에서 멀 때만 색이 칠해집니다.
  - 보고 줄에 `control=`, `a2_mips=`, `control_ratio=`, `control_separate=`, `mark=`, `a2_runs=`가 더해집니다.
- **CI**(#59): 세 워크플로의 Linux 러너를 `ubuntu-26.04`와 `ubuntu-26.04-arm`으로 명시했습니다. i386 Debian 컨테이너는 `--security-opt seccomp=unconfined`로 띄웁니다.
- **문서**: #59와 #60의 설계, 작업 지시서, 작업 로그. 분석 `robustness-fuzz.md`, `browser-wasm.md` 3.2절. 가이드 `robustness-fuzz.md`, `browser-tests.md`, `benchmark.md`. ARCHITECTURE, README(`GIT_TAG v0.0.28`). #53 작업 로그의 캠페인 확인 절.

## 발견

- **Ubuntu 26.04의 i386 컨테이너**: 이 이미지의 Docker(29.4.2) 기본 seccomp 프로필이 i386 프로세스의 소켓 호출을 ENOSYS로 막습니다. apt가 저장소에 닿지 못했습니다. amd64 컨테이너는 괜찮고, 커널의 32비트 호환도 정상입니다. GCC 15.2.0과 Clang 21.1.8의 `-Werror` 빌드는 바로 통과했습니다.
- **재번역 억제의 효과**(Intel Core i5-7200U, WSL2, 억제를 끈 빌드와 번갈아 세 번): IR 평가기의 `smc`에서 번역이 118,494번에서 2번으로 줄었습니다. 처리량은 2.40~2.44에서 2.57~2.63 MIPS로 올라 인터프리터 수준이 되었습니다. 다른 워크로드는 변동 안에서 같습니다.
- **모듈 수와 처리량**: 블록이 많은 `blocks`에서는 묶음 64가 16보다 Chromium, Firefox, Node 모두에서 빠릅니다. 모든 블록이 설치된 뒤의 프레임도 약 14% 빠르니, 살아 있는 모듈 수 자체가 호출 비용에 듭니다. 대가로 첫 프레임이 늦어집니다. 기본값(16)은 소비자 게스트의 측정과 함께 정하기로 하고 바꾸지 않았습니다.
- **인터프리터의 페이지 단위 무효화**: `smc`는 번역과 상관없이 인터프리터부터 `alu`의 6분의 1 수준입니다. 코드 페이지에 쓸 때마다 그 페이지의 디코드 캐시가 통째로 버려지기 때문입니다. 후속 후보입니다.
- **Zen 5의 CMPS 판정**: v0.0.28 캠페인에서 처음 Zen 5 러너가 int-i386을 맡아, #53에서 넓힌 판정이 확인되었습니다(아래).

## 소비자 영향

- 공개 계약에는 `TranslationStats::blocks_invalidated` 필드만 더해졌습니다. 어댑터는 고칠 것이 없습니다.
- 동작: 번역이 켜진 소비자에서 코드 페이지에 자주 쓰는 게스트는 번역을 덜 시도합니다. 한 번 코드가 바뀐 블록은 다시 번역되기까지 더 오래 기다립니다(최대 문턱의 64배). 결과는 인터프리터와 같습니다.
- re2DJ의 i386 컨테이너는 이미 `seccomp=unconfined`를 써서 Ubuntu 26.04 전환의 영향이 없습니다.

## English

# rex86 v0.0.29

Small follow-ups (#59) and #49's follow-up (#60): re-translation of blocks whose code changes is damped, the robustness harness gains a watchdog, and the compare page runs a same-session A/A alongside; CI moves to Ubuntu 26.04 runners.

## Changes

- **Damped re-translation** (#60):
  - Block entries count only while the head page keeps its code, so a block on a page written more often than the threshold is never translated.
  - When a translation (a waiting one included) is dropped because its code changed, translating again takes 2, 4, … up to 64 times the threshold in entries, sharing #49's eviction count (`backoff`).
  - The public contract's `TranslationStats` gains `blocks_invalidated`, the translations dropped because their code changed.
- **Benchmark**: the `smc` workload writes its own code page (#60), storing to a variable on the page every iteration and rewriting an ADD's immediate every 16th; it stays out of `mixed`, so comparisons across versions hold. Translation engines' `modules_submitted=` line gains `blocks_invalidated=`.
- **A watchdog in the robustness harness** (#59): a case past 60 seconds prints `VIOLATION seed=<S>: watchdog: ...` and fails the run; `--case-seconds N` sets the limit (0 for off); wasm32 builds without threads have none.
- **An A/A control on the compare page** (#59): `compare.html` runs A once more (A2) and shows an A2/A column, on by default at 1.5 times the runs.
  - A row whose A2/A meets the marking rule shows as unsteady.
  - B/A is colored only when it lies further from 1 than A2/A.
  - Report lines gain `control=`, `a2_mips=`, `control_ratio=`, `control_separate=`, `mark=` and `a2_runs=`.
- **CI** (#59): the three workflows name their Linux runners `ubuntu-26.04` and `ubuntu-26.04-arm`, and the i386 Debian container runs with `--security-opt seccomp=unconfined`.
- **Documents**: #59's and #60's designs, work orders and work logs; the analyses `robustness-fuzz.md` and `browser-wasm.md` section 3.2; the guides `robustness-fuzz.md`, `browser-tests.md` and `benchmark.md`; ARCHITECTURE and README (`GIT_TAG v0.0.28`); and a campaign confirmation section in #53's work log.

## Findings

- **The i386 container on Ubuntu 26.04**: this image's Docker (29.4.2) default seccomp profile fails an i386 process's socket calls with ENOSYS, so apt reached no repository. amd64 containers are fine, and so is the kernel's 32-bit compatibility. GCC 15.2.0 and Clang 21.1.8 passed the `-Werror` builds as they were.
- **The damping's effect** (Intel Core i5-7200U, WSL2, three runs alternating with a build without it): on the IR evaluator, `smc` translations fell from 118,494 to 2 and throughput rose from 2.40–2.44 to 2.57–2.63 MIPS, the interpreter's level; other workloads match within the variation.
- **Module count against throughput**: on the many-block `blocks`, 64-block batches beat 16 in Chromium, Firefox and Node, frames after every block is installed included (some 14%), so the number of live modules itself costs calls; the price is a later first frame. The default (16) stays, to be settled with consumer guest measurements.
- **The interpreter's per-page invalidation**: `smc` runs at a sixth of `alu` on the interpreter already, whatever the translation, because each write to the code page drops the page's whole decode cache; a follow-up candidate.
- **CMPS on Zen 5**: v0.0.28's campaign put int-i386 on a Zen 5 runner for the first time, confirming the judgment #53 widened (below).

## Consumer impact

- The public contract only gains `TranslationStats::blocks_invalidated`; adapters need no change.
- Behavior: with translation on, a guest writing its code pages often attempts fewer translations, and a block whose code changed once waits longer before translating again (up to 64 times the threshold); results stay the interpreter's.
- re2DJ's i386 container already uses `seccomp=unconfined` and is unaffected by the Ubuntu 26.04 move.
