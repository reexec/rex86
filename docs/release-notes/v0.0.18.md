# rex86 v0.0.18

인터프리터의 빠른 경로입니다. 디코드 캐시와 묶음 인출(#34), 블록 단위 실행(#35)을 더했습니다. 결과는 바뀌지 않으며, 같은 기계에서 x86-64 GCC Release의 mixed 워크로드가 3.6 MIPS에서 12.5 MIPS가 됐습니다. JIT가 금지된 호스트(iOS 네이티브)에서는 이 인터프리터가 성능의 바닥입니다.

## 변경 사항

- **디코드 캐시**(#34, `src/interp/decode_cache.{h,cpp}`):
  - 직접 사상 4,096칸입니다. 적중하면 인출과 Zydis 디코드를 건너뜁니다.
  - `Cpu`는 64명령을 실행한 뒤 캐시를 만듭니다. 그래서 짧게 쓰는 `Cpu`는 비용을 내지 않습니다. 예열 길이는 CMake 옵션 `REX86_DECODE_CACHE_WARMUP`으로 바꿀 수 있습니다.
  - 자기 수정 코드는 `PageAttributeTable`의 페이지별 세대로 무효화합니다. `kTranslated`가 지워질 때 세대가 1 오르므로, 메모리를 공유하는 여러 `Cpu`의 낡은 칸이 한꺼번에 무효가 됩니다.
- **묶음 인출**(#34): 캐시를 놓치면 15바이트 창을 limit, 인출 가능한 페이지, 버퍼 끝 가운데 가장 짧은 곳에서 자르고 한 번에 읽습니다. 폴트 종류와 주소는 예전 바이트 단위 인출과 같습니다.
- **블록 단위 실행**(#35):
  - `interp::RunBlock`은 `Cpu::Run`의 검사 사이에서 명령을 연달아 실행합니다.
  - 다음 경우에는 `Run`으로 돌아옵니다. 예산이나 예열 끝에 닿을 때, 정지 요청이나 대기 인터럽트(`attention`)가 있을 때, 게이트 필터가 양성일 때, 명령이 단순히 retire하지 않을 때입니다.
  - 게이트, 인터럽트 전달과 STI·MOV SS 그림자, 정지 요청, SMC, 정확한 폴트의 의미는 같습니다.
  - 측정으로 찾은 명령당 비용을 줄였습니다. 미스 경로를 `noinline`으로 분리했고, 결과를 제자리에 쓰며, `SlotOf`를 constexpr 표로 바꿨습니다.
- **wasm32 빌드**(#35 후속): 정지와 `attention` 플래그를 `std::atomic<bool>` 기반의 이동 가능한 `Cpu::AtomicFlag`로 바꿨습니다. Emscripten 3.1.74의 libc++ 18에 `std::atomic_ref`가 없기 때문입니다. 코딩 스타일에 "CI가 검증하는 가장 오래된 표준 라이브러리에 있는 기능만 쓴다"는 규칙을 더했습니다.
- **결함 수정**(#34 중 발견, #29에서 생긴 결함): `ExecuteMmx`가 SSE2의 `CVTPD2PI mm, m128`을 받아 8바이트 버퍼에 16바이트를 읽었습니다. 이제 MMX/SSE 집합만 받고, MM/XMM 원본 읽기는 너무 큰 피연산자를 거절합니다.
- **문서**: #34와 #35의 설계, 지시서, 작업 로그를 썼습니다. 분석 `interpreter-performance.md`, ARCHITECTURE, README의 현재 수치도 갱신했습니다.

## 소비자 영향

- 공개 계약이 바뀌었으므로 소비자는 다시 빌드해야 합니다.
  - `Cpu`는 이제 이동만 되고 복사할 수 없습니다. 크기와 ABI도 바뀌었습니다.
  - `Cpu::EngineMemoryBytes`와 `PageAttributeTable::Generation`이 더해졌습니다(추가뿐).
- **이미 실행된 게스트 코드를 고치는 소비자는 `Cpu::InvalidateCode`를 불러야 합니다.** rePIU의 HLE 패치나 re2DJ의 import 썽크 재작성이 그런 경우입니다. 원래 계약이었지만 이제 인터프리터도 이에 기댑니다.
- 메모리는 `Cpu`마다 실행을 시작하면 약 4.6 MB(x86-64) 또는 4 MB(wasm32)가 더 듭니다. 게이트를 등록하면 필터 8 KiB가 더 듭니다.
- 두 소비자의 tag 올림 작업은 tag push 뒤에 시작합니다.

## English

# rex86 v0.0.18

The interpreter's fast path: a decode cache with bulk fetching (#34) and block-level execution (#35). No result changes; on the same machine the x86-64 GCC Release build's mixed workload went from 3.6 to 12.5 MIPS. On JIT-forbidden hosts (native iOS) this interpreter is the performance floor.

## Changes

- **The decode cache** (#34, `src/interp/decode_cache.{h,cpp}`):
  - 4,096 direct-mapped slots. A hit skips fetching and Zydis decoding.
  - A `Cpu` makes its cache after running 64 instructions, so short-lived Cpus never pay for it. The CMake option `REX86_DECODE_CACHE_WARMUP` overrides the warm-up length.
  - Self-modifying code is invalidated through per-page generations in `PageAttributeTable`. A generation rises by 1 when `kTranslated` clears, so the stale slots of every `Cpu` sharing the memory become invalid at once.
- **Bulk fetching** (#34): on a miss, the 15-byte window is cut at the shortest of the limit, the last fetchable page and the buffer end, then read at once. Fault kinds and addresses are those of the old byte-wise fetch.
- **Block-level execution** (#35):
  - `interp::RunBlock` runs instructions back to back between `Cpu::Run`'s checks.
  - It returns to `Run` at the budget or the end of the warm-up, on a stop request or pending interrupt (`attention`), when the gate filter is positive, and when an instruction does not simply retire.
  - Gates, interrupt delivery with the STI and MOV SS shadows, stop requests, SMC and precise faults keep their meaning.
  - The per-instruction costs found by measurement were cut: the miss path split off as `noinline`, results written in place, and `SlotOf` turned into a constexpr table.
- **The wasm32 build** (#35 follow-up): the stop and `attention` flags became the movable `Cpu::AtomicFlag` over `std::atomic<bool>`, because Emscripten 3.1.74's libc++ 18 lacks `std::atomic_ref`. The coding style gained a rule: use only the standard-library features of the oldest standard library CI checks.
- **A defect fixed** (found during #34, introduced in #29): `ExecuteMmx` took SSE2's `CVTPD2PI mm, m128` and read 16 bytes into an 8-byte buffer. It now takes only the MMX/SSE sets, and the MM/XMM source readers refuse oversized operands.
- **Documents**: the #34 and #35 designs, work orders and work logs. The analysis `interpreter-performance.md`, ARCHITECTURE and README's current figures were updated.

## Consumer impact

- The public contract changed, so consumers must rebuild.
  - `Cpu` is now move-only and cannot be copied. Its size and ABI changed.
  - `Cpu::EngineMemoryBytes` and `PageAttributeTable::Generation` are new (additions only).
- **A consumer changing guest code that has already run must call `Cpu::InvalidateCode`.** rePIU's HLE patches and re2DJ's import-thunk rewrites are such cases. This was always the contract, but the interpreter now relies on it too.
- Memory: about 4.6 MB (x86-64) or 4 MB (wasm32) more per `Cpu` once it runs, plus an 8 KiB filter once gates are registered.
- Both consumers' tag-bump tasks start after the tag is pushed.
