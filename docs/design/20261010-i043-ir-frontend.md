# #43 설계 : IR, x86 → IR 프런트엔드, IR 평가기 / #43 design : the IR, the x86-to-IR frontend and the IR evaluator

이슈: [#43](https://github.com/reexec/rex86/issues/43) | 상위 설계: [#42](20261010-i042-phase3-translation.md) 결정 2, 3, 4, 11 | 지시서: [20261010-i043](../work-orders/20261010-i043-ir-frontend.md) | 로그: [20261010-i043](../work-logs/20261010-i043-ir-frontend.md)

3단계의 첫 하위 이슈다. 번역 실행기(#44)와 백엔드(#45)가 쓸 IR, x86 블록을 IR로 내리는 프런트엔드, IR을 그대로 해석하는 평가기를 만들고, 인터프리터와의 차등으로 검증한다. 이 이슈는 `Cpu::Run`을 바꾸지 않는다. 공개 계약도 바뀌지 않는다.

*The first sub-issue of phase 3: the IR the runtime (#44) and backends (#45) will use, the frontend lowering x86 blocks to it, and an evaluator interpreting it directly, all verified differentially against the interpreter. `Cpu::Run` and the public contract do not change here.*

## 결정 2: IR의 값과 연산 / Decision 2: IR values and operations

* **값**: 모든 값은 32비트 부호 없는 정수다. 폭은 연산이 명시적으로 마스크한다. 값은 블록 안에서 한 번 정의된다(번호로 가리킴).
* **연산**(첫 판):

| 묶음 | 연산 |
|---|---|
| 상수와 상태 | `Const`, `GetReg r`, `SetReg r v`(32비트 전체), `GetFlag f`, `SetFlag f v`(0 또는 1) |
| 산술과 논리 | `Add`, `Sub`, `And`, `Or`, `Xor`, `Not`, `Mul`(하위 32비트), `MulHiS`, `MulHiU` |
| 시프트 | `Shl`, `Shr`, `Sar`. 개수는 0~31로 정의한다(프런트엔드가 마스크) |
| 비교와 선택 | `Eq`, `Ne`, `LtU`, `LtS`, `Select c a b` |
| 플래그 도우미 | `Parity v`(하위 바이트 짝수 패리티면 1) |
| 메모리 | `Check seg off bytes write`, `Load seg off bytes`, `Store seg off bytes v` |
| 흐름 | `Begin i eip`(명령 경계), `ExitIf c kind eip`, `Exit kind eip` |

* 부분 레지스터(AL, AH, AX)는 프런트엔드가 `GetReg`와 마스크, `Or`로 합친다. IR에는 32비트 레지스터만 있다.
* 연산의 의미는 평가기가 정한다(결정 5). 백엔드는 같은 의미를 내야 한다.

*All values are 32-bit unsigned integers, widths masked explicitly by the operations, each defined once in the block and referred to by number. The first operation set is the table above; partial registers (AL, AH, AX) are merged by the frontend with `GetReg`, masks and `Or`, so the IR holds 32-bit registers only. The evaluator defines the operations' meaning (decision 5), which backends must reproduce.*

## 결정 3: 메모리 검사와 탈출 / Decision 3: memory checks and exits

`Check seg off bytes write`는 인터프리터의 접근이 폴트 없이 그대로 끝날 **충분 조건**을 본다. 하나라도 어긋나면 블록은 현재 명령의 시작에서 **인터프리터 탈출**을 한다.

1. 쓰기면 세그먼트가 writable이다.
2. 세그먼트가 평탄하지 않으면 present이고 `off <= limit`, `limit - off >= bytes - 1`이다.
3. 선형 주소 `base + off`부터 `bytes`바이트가 게스트 메모리 안이고, 모든 페이지가 `kMapped`와 `kRead`(쓰기면 `kWrite`)를 가진다.
4. 쓰기면 어느 페이지도 `kTranslated`가 아니다(SMC, #42 결정 6).

* 이 조건은 `access.cpp`의 `Linearize`, `ReadVirtual`, `WriteVirtual`이 성공하는 조건과 같다. 4만 다르다. 인터프리터는 그 경우에도 성공하지만 플래그를 지운다. 번역 코드는 그 일을 인터프리터에 맡긴다.
* **탈출은 언제나 옳다.** 인터프리터가 그 명령을 처음부터 다시 실행하기 때문이다. 그래서 검사는 보수적이어도 된다. 예: `SHL [m], CL`은 CL이 0이면 쓰지 않지만, 번역 코드는 쓰기 검사를 먼저 한다. 실패하면 인터프리터가 맞게 처리한다.
* **검사 먼저**(#42 결정 3): 한 명령의 모든 `Check`는 그 명령의 첫 `SetReg`, `SetFlag`, `Store`보다 앞에 둔다. 그래서 탈출할 때 상태는 명령 시작 그대로다.
* `Begin i eip`는 명령 i의 경계를 표시한다. 그 뒤의 `Check` 실패와 `ExitIf`는 단계 수 `i`(명령 i 앞까지 끝난 명령 수)를 보고한다.

*`Check seg off bytes write` tests a **sufficient** condition for the interpreter's access to complete without a fault, the four conditions above; if any fails, the block takes an **interpreter exit** at the current instruction's start. The conditions are those under which `access.cpp`'s `Linearize`, `ReadVirtual` and `WriteVirtual` succeed, but for the fourth: there the interpreter succeeds and clears the flag, which translated code leaves to it. An exit is always correct, since the interpreter reruns the instruction from its start, so checks may be conservative: `SHL [m], CL` writes nothing when CL is 0, yet translated code checks the write first, and on failure the interpreter does the right thing. Check first (#42, decision 3): every `Check` of an instruction precedes its first `SetReg`, `SetFlag` or `Store`, so an exit leaves the instruction's starting state. `Begin i eip` marks instruction i's boundary; a failed `Check` or an `ExitIf` after it reports `i` steps (the instructions completed before i).*

## 결정 4: 블록 형성과 적용 범위 / Decision 4: block formation and coverage

* **입력**: CPU 상태(EIP, CS와 SS의 모드), 게스트 메모리, 게이트 판정 함수, 최대 길이(64).
* **전제**: CS가 평탄하고 32비트(`default_32bit`), SS가 32비트다. 아니면 블록을 만들지 않는다. 이 전제를 블록에 기록하고, 실행기(#44)가 실행 전에 확인한다. 평탄한 CS에서 분기 목적지 검사(`CheckBranchTarget`)는 실패하지 않는다.
* **인출**: 인터프리터와 같은 조건(`kMapped`, `kExecute`)으로 읽을 수 있는 바이트만 쓴다. 다음 명령을 인출할 수 없으면 그 앞에서 블록을 끝낸다(`Exit kInterpret`). 인터프리터가 폴트를 낸다. 블록은 페이지 둘까지 걸칠 수 있다.
* **끝**: 제어 이동(마지막 명령으로 내림), 다루지 않는 명령 앞, 게이트 판정이 양성인 주소 앞(첫 명령 제외), 최대 길이.
* **첫 범위**(형태마다 피연산자 8, 16, 32비트, 주소 크기 32비트만):
  * MOV(r/m, r, imm; 세그먼트 레지스터 제외), MOVZX, MOVSX, LEA, XCHG(r, r/m), NOP
  * ADD, ADC, SUB, SBB, CMP, AND, OR, XOR, TEST, INC, DEC, NEG, NOT
  * SHL, SHR, SAR, ROL, ROR(개수 1, imm8, CL. RCL, RCR은 제외)
  * IMUL(1, 2, 3 피연산자)
  * PUSH, POP(r, m, imm; 세그먼트 레지스터 제외, 피연산자 32비트)
  * Jcc, JMP(rel, r/m), CALL(rel, r/m), RET(imm16 포함), SETcc, CMOVcc. 분기는 피연산자 32비트만.
* **제외**: LOCK 접두어, 주소 크기 16비트, 문자열, x87, MMX/SSE, 세그먼트 적재, PUSHF/POPF, 이벤트가 있는 명령. 모두 인터프리터가 맡는다.

*Inputs are the CPU state (EIP, the CS and SS modes), guest memory, a gate predicate and the maximum length (64). The block assumes a flat 32-bit CS (`default_32bit`) and a 32-bit SS, or none is formed; the assumption is recorded in the block and the runtime (#44) checks it before running, and with a flat CS the branch-target check (`CheckBranchTarget`) never fails. Fetching uses only bytes the interpreter could fetch (`kMapped`, `kExecute`); when the next instruction cannot be fetched, the block ends before it (`Exit kInterpret`) and the interpreter raises the fault; a block may span two pages. A block ends at a control transfer (lowered as its last instruction), before an uncovered instruction, before an address the gate predicate flags (not its first instruction), or at the maximum length. The first coverage, with 8-, 16- and 32-bit operands and 32-bit addressing only, is the list above; excluded are the LOCK prefix, 16-bit addressing, strings, the x87, MMX/SSE, segment loads, PUSHF/POPF and instructions with events, all left to the interpreter.*

## 결정 5: 평가기 / Decision 5: the evaluator

* `Evaluate(block, CpuState&, GuestMemory&)`는 연산을 차례로 실행한다. `SetReg`, `SetFlag`, `Store`는 곧바로 상태와 메모리에 반영한다. 그래서 탈출할 때 상태가 정확하다는 조건(#42 결정 4)이 저절로 성립한다.
* **결과**: `{kind, eip, steps}`. `kind`는 `kContinue`(EIP에서 이어감) 또는 `kInterpret`(EIP의 명령은 인터프리터가 실행). 탈출하면 평가기가 EIP를 상태에 쓴다.
* `Store`는 `Check`를 통과한 뒤에만 오므로, 평가기는 `GuestMemory`의 쓰기를 그대로 부른다. `kTranslated`가 없는 페이지에만 쓰므로 무효화가 필요 없다.

*`Evaluate(block, CpuState&, GuestMemory&)` runs the operations in order, `SetReg`, `SetFlag` and `Store` landing in state and memory at once, so the precise-state-at-exit condition (#42, decision 4) holds by construction. It returns `{kind, eip, steps}`, `kind` being `kContinue` (continue at EIP) or `kInterpret` (the interpreter runs the instruction at EIP), and writes EIP into the state on exit. A `Store` always follows a passing `Check`, so the evaluator calls `GuestMemory`'s writes directly; it writes only pages without `kTranslated`, so no invalidation is needed.*

## 결정 6: 최적화 / Decision 6: optimization

* **죽은 쓰기 제거**: `SetFlag f`(또는 `SetReg r`) 뒤에 같은 대상의 쓰기가 오고, 그 사이에 그 대상을 읽는 연산도 탈출할 수 있는 연산(`Check`, `ExitIf`)도 없으면 앞의 쓰기를 지운다. 탈출 지점의 상태는 정확해야 하기 때문이다.
* **죽은 값 제거**: 결과를 아무도 쓰지 않는 순수 연산을 지운다. 위의 제거로 쓰이지 않게 된 플래그 계산이 여기서 사라진다.
* 차등 테스트는 최적화한 블록과 하지 않은 블록 둘 다로 돈다.

*Dead-write removal: a `SetFlag f` (or `SetReg r`) is removed when a later write to the same target follows with no operation in between reading it or able to exit (`Check`, `ExitIf`), since the state at an exit must be precise. Dead-value removal: pure operations whose results nobody uses are removed, which is where the flag computations orphaned above disappear. The differential tests run blocks both optimized and not.*

## 결정 7: 검증 / Decision 7: verification

| 테스트 | 방법 | 기준 |
|---|---|---|
| 형태별 | 1, 2바이트 opcode × 무작위 ModRM/SIB/변위/즉값 × 66, 세그먼트 접두어. 디코드해 첫 범위에 드는 것만. 무작위 상태(레지스터의 일부는 매핑된 영역을 가리킴, 무작위 플래그, 무작위 메모리). 같은 사본에서 인터프리터 `Step` 하나와 명령 하나짜리 블록의 평가 | 레지스터, EFLAGS, EIP, 메모리가 같다. 평가기가 탈출하면 상태가 시작 그대로다 |
| 블록 | 첫 범위의 명령을 무작위로 1~16개 이은 코드. 평가기 한 번과, 인터프리터가 같은 수의 단계를 실행한 결과 | 같은 기준. 탈출하면 단계 수와 EIP도 같다 |
| 경계 | 매핑 밖, 읽기 전용 페이지, `kTranslated` 페이지, 평탄하지 않은 세그먼트의 limit, 페이지에 걸친 접근, 게이트 앞의 블록 끝, 인출할 수 없는 다음 명령 | 탈출과 시작 상태 |
| 범위 계량 | 형태별 테스트에서 실제로 비교된(탈출하지 않은) 사례의 수를 mnemonic마다 센다 | 첫 범위의 모든 mnemonic이 0보다 크다 |
| 긴 실행 | `rex86_irdiff --cases N --seed S`. 같은 생성기로 많이 돌린다 | 불일치 0 |

* ctest에는 단위 테스트(짧은 규모)와 `rex86_irdiff`의 smoke를 등록한다. 다섯 호스트 CI에서 돈다.

*Per form: one- and two-byte opcodes with random ModRM/SIB/displacement/immediates and 66 and segment prefixes, decoded and kept when in the first coverage; random states (some registers pointing into the mapped region, random flags, random memory); one interpreter `Step` and the evaluation of a one-instruction block on identical copies, which must agree in registers, EFLAGS, EIP and memory, an evaluator exit leaving the starting state. Blocks: random runs of 1 to 16 covered instructions, one evaluation against the interpreter running as many steps, with the same criterion plus the step count and EIP on exit. Edges: unmapped, read-only and `kTranslated` pages, non-flat segment limits, page-straddling accesses, a block ending before a gate, an unfetchable next instruction. Coverage count: the compared (non-exiting) cases per mnemonic, every first-coverage mnemonic above zero. Long runs: `rex86_irdiff --cases N --seed S` on the same generator, zero mismatches. ctest registers the unit tests (small scale) and an `rex86_irdiff` smoke, on the five CI hosts.*
